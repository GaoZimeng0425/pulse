# 废纸篓是删除的默认路径而非原则;永久删除须显式勾选

ADR-0008 把「一律进废纸篓」列为删除的多重闸门之一。2026-11-01 应用卸载器
grill 中用户澄清:进废纸篓是技术默认(可悔的实现),不是产品原则——但「默认
可悔」的纪律不变,永久路径必须由用户逐次显式选择。

决定(2026-11-01 用户拍板):

- 废纸篓是一切删除的**默认**去向;可悔性由默认保证,不靠禁止永久路径保证。
- 永久删除的唯一形态 = 卸载流程的显式「彻底删除」勾选(brew / 非 brew 统一):
  勾 = 不经废纸篓(brew 走 `--zap`),确认清单逐行标「永久删除」+ 页脚明示不可
  恢复;默认不勾、不记忆跨次。
- 清理页(开发者垃圾)不提供该勾选:那里的永久路径仍是「废纸篓 → 清空废纸篓」
  两段式,ADR-0008 原样有效。
- 后续任何新的永久删除入口都须走同款显式勾选 + 强化确认,不得做成默认。

被否的替代:①把「一律废纸篓」当原则、卸载器不提供永久路径——brew 的彻底卸载
本就永久,且对"点名删一个 app"再绕废纸篓是多余一步;②清理页也加同款勾选——
批量勾选场景把「永久」混进默认流,扩大误删面,两段式已经给出永久出口。

后果:ADR-0008 中「一律进废纸篓」此后读作「清理页的默认去向,而非禁令」;
「清空废纸篓」保留独立按钮 + 二次确认不变;卸载器永久路径的确认清单必须逐行
标注去向,清理历史以去向字段如实区分「废纸篓 / 永久删除 / 已卸载(brew,永久)」。
