# DESIGN.md 只收原则与组件规范;页面实现细节住在代码旁

DESIGN.md 曾被当作「已拍板样式登记处」:每定一个细节记一句,文件从 10-17 的 191 行
涨到 866 行,规则与历史混在一起,并以「已知偏差」记账管理不统一之处。2026-11-23
用户在清理空间地图路径栏时质疑这种写法,拍板改为:DESIGN.md 只写原则与组件规范,
项目统一、不留偏差。

决定(2026-11-23 用户拍板):

- **三个词**:**原则** = 全 app 成立、不提任何页面的规矩;**组件规范** = 一个通用
  界面件长什么样、有哪些状态、什么时候用;**实现细节** = 只对某一屏成立的摆法、
  交互、文案。判定法:把句子里的页面名遮掉,还成立的是前两类,不成立的是实现细节。
- DESIGN.md 只收原则、组件规范与令牌。实现细节写在该页代码旁的注释里,按统一标准
  重写(只写代码读不出来的、不写历史、每条规矩只有一个家),不整块搬运。
- 只在一处使用的件分两种:业务专用件(空间地图本体、热力墙、项目大卡等)按实现细节
  处理;通用界面件(面包屑、搜索框、勾选框、图表悬停浮层、卡头文字按钮)即使只有
  一处使用也立组件规范。
- 规范里没有「例外」「偏差」。被登记为例外的(设置图标砖的渐变与投影、图表实现
  分工、图标字号不受文字五档约束)改写为规范条目;未改完的统一项一次改完,并用
  lint 规则防止回潮。

被否的替代:①维持登记处写法——agent 动手前读到的三分之二是某一页的细节,且账本
会漏记(清字号一轮漏了 2 处);②把逐屏规格外移到独立文档再从 DESIGN.md 引用——
只是把同一堆内容换个地方,与代码分离后更易漂移;③整块原文搬运到代码文件头——
留下的是按旧写法积累的叙述,而代码里本就已有大量同义注释。

后果:AGENTS.md 的「已拍板样式不得静默回退」改述为「规范与页面规格里已定的样式
不得静默改」;「动到对应文件时顺带收编」的偏差处理方式废止;新增通用界面件时先在
DESIGN.md 立规范再实现。
