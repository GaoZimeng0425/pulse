# 清理一律用户态完成,不扩 root 帮手权限

P3 的 root 常驻 daemon(SMAppService 注册,Energy Impact 真值)已在跑。清理功能理论上
可以借它清 /Library 级系统垃圾——帮手进程有权限,加一个删除通道技术上很顺。

决定(2026-10-28 用户拍板"定死"):

- 清理的扫描与删除全部在用户态完成,FDA 够用;root 帮手维持只读能耗职责,**永不获得
  删文件能力**。
- /Library 级系统垃圾(需管理员权限)不清理——量小,放弃不心疼。

被否的替代:①root 帮手加删除通道——帮手被攻破即任意文件删除,root 攻击面量级扩张,
"能删文件"与"能读能耗"是两种完全不同的信任等级;②删除时临时 admin 提权——每次弹系统
密码框,体验与那点系统垃圾的收益不成比例。

后果:帮手协议面保持只读,后续给帮手加能力的提案都不得包含写 / 删文件系统;
将来若真要清系统级垃圾,须以新 ADR 明确推翻本决定,不得默默扩权。
