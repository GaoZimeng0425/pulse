# 清理删除走安全白名单,默认拒绝;空间地图 v1 只读

Pulse 从纯监视器升级为能删文件的工具,第一命题是"敢删"而不是"搜到":搜到只回收空间,
删错(在用的项目、唯一一份的个人文件)的代价远大于收益。空间地图为回答「空间去哪了」必须
显示盘上一切——包括任何规则都永远无法担保的个人文件。

决定(2026-10-28 grilling 三轮,用户拍板):

- **唯一删除入口 = 白名单识别的清理页**:只删命中已知安全路径模式的条目,未识别者不显示、
  不可删。「能删的地方」永远等于「白名单担保过的地方」。
- **空间地图 v1 只读**(下钻 + 跳 Finder):地图上每个块都是规则表认不出的东西;若地图可
  直删,机器担保过的 node_modules 与机器无法担保的唯一一份视频用同一手势可删,安全差别隐形。
  二期可议 C 混合形态(白名单识别过的块在地图上标出、可删),那是升级不是开口子。
- 删除动作的多重闸门:两档安全标签(可安全清理默认可勾 / 先检查默认不勾)+ 清单默认全不勾
  + 确认清单 + 一律进废纸篓 + 在用保护**删除前重查、判定永不缓存**。
- 排除目录只收窄扫描、永不扩大;动态拒否(在用 / 排除)结果不缓存。

被否的替代:①地图内直删(DaisyDisk 式)——等于给任意路径删除开口,确认流程再重也改变不了
"无担保删除"的本质;②黑名单模型(列出不许删的)——漏登一条就是灾难,方向反了;③定时自动
清理"安全项"——把不可恢复操作自动化,信任未建立时爆炸半径随在线时间放大。

后果:规则表成为安全边界的本体,改它必须过登记完整性测试(每条内置规则至少一个正例命中,
新增规则不写用例过不了测试);清理历史永久保留,作为事后追溯的唯一记录;「清空废纸篓」
是全系统唯一不可逆操作,独立按钮 + 汇总所有卷的二次确认。
