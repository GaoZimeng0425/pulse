# 清理可按次借管理员权限;能力用完即止,特权助手不获得动文件的能力

ADR-0009(2026-10-28)定死「清理一律用户态完成,永不借 root」,当时的权衡是「那点系统垃圾
不值得」。2026-11-26 用户改变目标——「希望我的电脑尽可能干净」「清理向 Mole 对齐」——
明确要求清理能处理系统目录里的东西。本决定推翻 ADR-0009。

决定(2026-11-26 grill 两轮,用户拍板):

- 涉及系统目录的清理可以要管理员权限,但**只在那一批动作发生时授权一次**:用户先在
  Pulse 的确认清单里过目,再弹系统管理员密码框,做完这一批即止。与 Mole 同款(平时不用
  sudo,用到才要密码)。
- Pulse 不常驻任何管理员能力:现有特权助手(root 守护进程)维持只读能耗职责,**不获得
  删除或移动文件的能力**;不新增常驻的特权删除通道。
- 权限只用于把系统级条目移进废纸篓;销毁仍只发生在用户点「清空废纸篓」(ADR-0010 不变)。
- 范围与 Mole 借管理员权限做的那几类一致:过期的系统日志与崩溃报告、可重建的系统缓存、
  程序已不存在的系统服务、卸载时留在系统目录里的东西。系统统一日志库不动。
- 公司安全软件(端点防护、设备管理、企业组网一类)永不列出。
- 提权一侧只处理确认清单里出现过的条目,并按登记过的路径形状自行复核,不信任 app 侧
  的判断。

被否的替代:①给特权助手加删除通道——机器上常驻一个能改系统文件的进程;助手一改用户
就要重新批准;助手现无接收指令的通道,要新加且未验证。②不给 Pulse 权限、只指路交给
Finder 删——不能批量,在跑的后台进程要重启才停。

后果:ADR-0009 自此作废,「清理一律用户态」改读作「默认用户态,系统目录按次授权」。
授权通道 2026-11-26 已探针验证(从终端进程发起:系统密码框一次,以 root 身份建并删一个
自建临时文件,5 秒,无残留;系统日志未见额外的隐私授权判定);从 Pulse 自己发起时的
表现留待实施时验证。该通道是系统脚本的管理员授权,Apple 文档对其现行态度未核实——
新系统上失效时须回到本决定重议,不得静默换道。真实提权路径不进自动化测试(同废纸篓
执行器纪律);提权侧的路径复核走脚本自测。

## 实施补充(2026-11-27,p7-cleaner/05 落地时确立)

「移进废纸篓下的专属子目录并把归属改为当前用户」不能由 root 直接做,落地时评审找到了
可稳定复现的提权路径:`/Library/Logs/DiagnosticReports` 对一个用户组可写,那个组里的
用户能把 root 文件的硬链接放进去(普通用户给 `/etc/hosts` 建硬链接实测可行);root
「移过去再按路径改归属」,改到的是 inode 本身。废纸篓目录又归用户所有,用户中途把它
换成符号链接,root 的移动就会被引到别处。所以流程定为两段:

1. root 只在自己的私有暂存目录(`/var/tmp` 下,粘滞位 + root 所有的上一级)里动文件:
   条目移进去 → 对着这份别人换不了的条目核对(普通文件、链接数为 1、属主、年龄)→
   改归属 → 把暂存目录交给调用者。改不了归属、或交接失败,就把条目(连同原来的属主与组)
   放回原处,整批没动。
2. 进废纸篓的专属子目录这一步,由 app 以调用者身份完成。

另立两条:提权代码的外部命令一律写绝对路径(不带授权的系统脚本通道实测原样继承调用方
的 PATH);后续给系统级规则加形状时照此办理,细则在根目录 CODING_STANDARDS 的
「提权纪律」。
