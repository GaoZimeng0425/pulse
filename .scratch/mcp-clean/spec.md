# mcp-clean:AI 经 MCP 真清理(只安全档 + app 确认框)

## 拍板(用户,2026-11-09)

1. 方向:让 AI 使用 Pulse 更顺——**AI 真能清理**,不是只出建议。
2. 范围:**只给 AI「可安全清理」档**。「先检查」档与在用保护项对 AI 不可见、不可删。
3. 确认:选 **B——app 弹确认框**。AI 帮选好清单,Pulse 主窗口弹既有确认单,用户点「移入废纸篓」才执行。v1 不另加设置开关:确认单即闸门。

## 架构(约束推导)

- pulse-mcp 是 AI 客户端拉起的独立进程,没有 Pulse.app 的 TCC 文件夹授权 → **执行必须交回在跑的 app**;顺带复用全部既有闸:安全档过滤、在用保护现查、删前 mtime 复核、废纸篓、清理历史。
- 确认单要人点 → 清理链路必须把主窗口拉到前台清礼页。`CleanerModel` 是主窗口 `@State`、**关窗即销毁**(p4 架构决定,不动)→ app 侧:
  - **列清单 = 常驻旁路**:app 常驻一个只读 `CleanerModel` 影子实例(同装配,只 restoreCache 不扫描不清删),主窗口开着时用窗口活实例(含实时重扫结果),关窗时用影子实例(缓存)。在用判定走 monitor 的活动板(app 常驻)。
  - **真清理 = 桥接窗口**:`McpCleanBridge`(app 常驻)持 pending 请求;窗口活时直连其模型,不活时走既有 `openMainWindowNotification`(tab=cleaner)+ 激活,窗口 onAppear 消费落点(与告警深链同机制)。
- IPC:app 内 `NWListener` 只听 127.0.0.1(动态端口),端点文件 `~/.Pulse/mcp-clean.json`({port, token, pid},0600);请求带 token 校验。同用户进程可读端点文件——可接受(同用户同信任域,确认单才是真闸)。
- MCP 两工具(中文 prose,与现有三工具同风格,如实标数据年龄):
  - `list_cleanable`:能安全清理的项(路径/大小/多久没动/所属组/数据年龄)。
  - `clean(paths)`:提交 → 等用户确认(10 分钟超时,超时撤单)→ 逐项结果(已清/在用跳过/有变动跳过/未识别路径)。

## 安全边界(全复用,不新造)

安全档 ∩ 非在用(现查)∩ 排除名单 ∩ 删前 mtime 复核 ∩ 废纸篓兜底 ∩ 清理历史留痕。MCP 提交的路径先与安全档清单求交,未识别/不安全路径原样退回不给删。

## 明确不做(v1)

- 不触发扫描(重扫仍由用户在 app 里点;清单标注扫描时间,AI 如实转述)。
- app 未运行时不降级读缓存(执行反正要 app;三个既有查询工具不变)。
- 不加设置开关、不做免确认模式。
