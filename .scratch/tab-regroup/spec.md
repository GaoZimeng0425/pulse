# tab-regroup:主窗口 tab 同类归位(2026-11-16 用户拍板,记档未开工)

## 背景

用户看着主窗口那排 13 个 tab 提出归组疑问,三刀定案:

1. **dev server / docker 是一类** → 合并成「服务」页(票 01)
2. **清理放磁盘旁边** → tab 相邻,不深并(票 02)
3. **空间地图应该在磁盘里** → 从清理页子页迁入磁盘页(票 03)

概念同族的既有证据:清理 tab 强调色本来就取磁盘令牌(`MetricTab.accent` 里 `cleaner → .disk`);
空间地图画的目录占用树与 MCP `disk_usage` 同源(都读清理扫描落盘的 SpaceScanCache)。

  「dev server 挂智能体页」与 agent-tab/06 三子页结构中的「开发服务」档(其余子页不动)。

## 更正记录(防再犯)

讨论中曾说「合并后 tab 少一个」——**错**:dev server 本非独立 tab,迁入容器页后
tab 总数仍为 13;本次是同类归位,不是减 tab。真减 tab 需深并,用户明确不选。

## 改完后的样子(用户视角)

1. 「服务」页(原容器位):上=开发服务卡(带「全部停止」),下=容器卡;智能体页剩
   消耗/会话两个子页。
2. tab 序:总览/CPU/内存/GPU/传感器/外设/**磁盘/清理**/网络/服务/智能体/电池/历史
   (清理紧随磁盘)。
3. 磁盘页五块:主卡、各卷明细、快照、读写排行、空间地图(点目录块跳「清理→全部清单」
   定位,动线保留但变跨页)。
4. 清理页四子页:总览/全部清单/应用/清理历史。

## 技术事实(分诊时核实)

- tab 选中态 rawValue 仅内存路由(告警广播 userInfo),**无 UserDefaults 落盘**——
  枚举改名不碰持久化,改后 ripgrep 引用面即可。
- 容器页是传感器家族门控成员(MetricSensorFamily.containers,p2-review/05);合页后
  门控跟着服务页走,dev server 无家族。
- 空间地图「去清理清单」现实现是壳层切子药丸闭包(CleanerSpaceMapView 交给壳层),
  迁页后需上提为跨 tab 路由(总览卡 onSelectTab 已有先例)。
