# p7-cleaner/11:项目产物对齐——目录种类 + 三类拒绝 + 近 7 天不自动勾

Status: ready-for-agent(2026-11-26 立)
Blocked by: 无(可立即开始)

## 目标

项目产物认得和对齐对象一样多的目录种类;名字叫对了但内容不该删的目录被拒绝;近 7 天有活动的产物不进「一键清理安全项」和「全选」。改之前:Python 工具链缓存这类产物不认;改之后:认得,而且正在做的项目不会被自动勾上。

## 范围

1. 目录种类补齐(对照对齐对象的产物清单,已知比我们多的有:pytest / mypy / tox / nox / ruff 的缓存目录、Gradle 本地目录等,实施时逐个对照)。每种带根标记与重建说明。注意同名不同归属:Gradle 本地目录出现在项目里算产物,在家目录下算全局缓存(归 10 票)。
2. 三类拒绝,任一命中即按拒绝条件处理:含部署密钥的目录、含嵌套代码仓库的目录、目录内有被代码仓库跟踪的文件。表现与现有「拒绝条件」字段同口径(不进可删清单);内容检查设条目数上限,超限 = 不敢担保 → 落「先检查」,不猜。
3. 近 7 天活动:以产物目录子树内最新变动为准(现有「项目年龄」口径)。7 天内有活动 → 不进自动勾选资格,表现与在用同待遇(不进一键清理安全项、不进全选;行上标「近 7 天有活动」);7 天外 → 按档位。
4. 不新建常驻采集:判定只用扫描树里已有的时间信息。
5. 自动勾选资格是单出处判定,05 之前的票若已改过它,本票在同一处改。

## 验收

- [ ] 夹具:每种新目录种类正例命中、档位正确
- [ ] 夹具:三类拒绝各一例;内容检查超限 → 「先检查」
- [ ] 夹具:6 天前有活动的产物不进一键清理与全选;8 天前的按档位进
- [ ] 夹具:在用判定(终端 / 构建进程在项目里)照旧生效,与近 7 天规则并存不冲突
- [ ] 目验:项目产物组出现此前不认的目录;近期在做的项目的产物不被自动勾选

## 测试

接缝 1 + 接缝 2(自动勾选资格);先例:项目产物规则用例、在用判定用例、一键清理计划用例。全量检查与真机验证由用户发起。
