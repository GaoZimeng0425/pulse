# p7-cleaner/05:运行时授权打通(细而完整的一刀)

Status: done(2026-11-28 合 develop @252f03c;真机目验待用户)
Blocked by: 无(01 已完成)

## 目标

用一条最小的系统级规则走通全链,证明「系统目录里的东西也能清、且可找回」:过期的系统崩溃报告(系统崩溃报告目录下超过 7 天的报告)→ 清单里出现 → 勾选 → 确认清单标「需要管理员权限」→ 弹一次系统管理员密码框 → 复核脚本逐条复核后移进废纸篓专属子目录并把归属改成当前用户 → 逐项结果如实报、清理历史照记。取消密码框 = 这一批都不动、勾选保留。改之前:系统目录里的东西我们不列也清不了;改之后:能清,且清错能从废纸篓找回。

## 范围

1. 新增可替换接口「把系统级条目移进废纸篓(需要授权)」:输入确认清单里的系统级条目与调用者身份;输出逐项结果(已移 / 跳过及原因 / 授权被取消 / 通道不可用)。与废纸篓执行器并列,装配点显式注入,不设默认值。
2. 真实实现:经系统管理员授权运行随包分发的复核脚本。通道 = 2026-11-26 探针验证过的系统脚本管理员授权。**从 Pulse 自己发起时的表现(是否多弹系统的同意框)在本票实施时验证并记进票面**;通道在新系统上失效时回到 ADR-0012 重议,不得静默换道。
3. 复核脚本(随包分发的只读资源):
   - 入参只有三样:清单文件路径、调用者 uid、废纸篓目标目录。清单文件由应用在用户临时目录创建,仅本人可读写。
   - 逐条复核:路径是绝对路径、不含 `..`、不是符号链接;命中已登记的系统级路径形状之一(本票只有「系统崩溃报告目录下、超过 7 天、普通文件」);属主是 root 或系统用户。任一不满足即跳过并回传原因。
   - 只做移动与改归属,不做删除;移动前再核一次年龄;目标已存在则加序号。
   - 逐项回传结构化结果行,由应用解析进结果横幅与清理历史。
   - 条目级失败不中断其余条目;脚本自身出错(非条目级)整批回传「通道不可用」。
   - *实施时这条改了形状(两段式、入参两样),缘由与改法见 Comments「实施」;本段保留立票时的原文。*
4. 执行编排:确认清单含系统级条目时先请求授权。取消 → 整批不动(用户态条目也不动)、勾选保留、如实提示「已取消授权,未做任何改动」;通道不可用 → 同上并提示原因;授权通过 → 先做系统级条目,再作用户态条目;逐项如实报,失败跳过继续,不静默。
5. 清空废纸篓:改归属后,现有清空逻辑不加权限就能处理(验证并加用例)。
6. 在用保护、删前复核、排除目录对系统级条目照常生效;删前复核读不到快照的条目按「缺少探测快照」跳过。
7. 现有特权助手零改动(ADR-0012:助手不获得动文件的能力)。
8. 复核脚本自测:不提权、不要密码,对夹具路径跑「哪些形状放行、哪些拒绝、年龄复核、移动与改归属、逐项结果」;挂进全量检查的脚本自测一步。自测里「删什么 / 绝不删什么」由用例钉住。
9. 安全纪律:脚本不走 eval、不把用户可控字符串拼进命令;路径参数严格引用;实施时按根目录 CODING_STANDARDS 的权限与并发条款自查。

## 验收

- [x] 假接口:通道不可用 → 如实提示,不静默
- [x] 脚本自测:合法形状放行;含 `..`、符号链接、未登记目录、年龄不足、非 root 属主各至少一例拒绝;移动后归属 = 调用者;结果行可解析
- [x] 历史:系统级条目带「需要管理员权限」条目标志,去向为废纸篓子目录

## Comments

**2026-11-28 实施(分支 `feat/p7-runtime-authorization`,四个提交 73da1f6 / 0f94798 / 1cf725e / 003be70,合 develop @252f03c;已推送已装机)**

- 规则(`SystemLevelRules`):系统崩溃报告目录直接下面满 7 天的普通文件,一条一个,带「需要管理员权限」,归「系统级」组、「可安全清理」档(认识的归安全档,于是「一键清理安全项」与 AI 清理的求交都会带上它们——确认清单里写明「其中 N 项在系统目录里」,点了才弹密码框)。扫描时为规则目录定向保留文件节点(按文件判年龄);每个文件各成一条,删前复核逐文件有效。装上新版后要重新扫描一次才会出现。
- 新接缝 `CleanSystemTrashExecutor`;执行编排(`CleanRunner.run`):删前复核照常 → 系统级条目先走授权通道 → 再做用户态条目。授权被取消 / 通道不可用 = 整批不动,回「没开始」(`CleanRunTermination` / `CleanRunAbort`),清理页结果卡与清理总览各出一张提示,勾选保留;清理历史不落。
- **复核脚本改成了两段式(与范围 3 的原文不同)**:
  - 第一段(root,`Pulse/Resources/SystemTrash/pulse-system-trash.sh`,入参两样:清单文件、调用者 uid):条目从登记目录移进 `/var/tmp` 下自己私有的暂存目录 → 在那里核对(普通文件、链接数为 1、属主、年龄)→ 改归属 → 把暂存目录交给调用者。
  - 第二段(应用,以用户身份):把暂存目录里的文件挪进 `~/.Trash/Pulse 系统级/<时间戳>/`,同名加序号、绝不覆盖。
  - 为什么不能由 root 直接「移进废纸篓再改归属」:见下方「首轮评审」。
- 环境隔离两道防线:启动系统脚本通道的进程给最小环境(PATH + 点名追加的变量),不继承 Pulse 的;脚本第一句在干净的环境里重跑自己。脚本外部命令一律写绝对路径。
- 其余落地:通道不可用的提示是「这一批没有清理,勾选保留」(脚本被强杀时说「都没有动」可能不属实);授权前先建好废纸篓子目录,进不去就不弹密码框;确认清单多一行预告会弹密码框(由系统工具 osascript 发起);等密码期间动作条点明会出现密码框;AI 清理桥对「没开始」如实回报;清空废纸篓对改了归属的子目录照常处理(用例钉住)。
- 测试:全量检查 1579 绿(核心包 + 特权助手包 1042、app 537)。脚本自测 `scripts/test-system-trash.sh` 172 条(挂进 check.sh);变异检查 `scripts/test-system-trash-mutations.sh` 38 条全部如预期(不挂 check.sh,改过脚本或自测后手跑,约八分钟);真实通道 20 条,其中 6 条不带授权走真脚本;核心层接口与编排 7 条、清理模型接线 7 条、AI 清理桥新增 2 条。

**三轮两轴评审(只读子代理并行)**

- 首轮:需求轴「有条件通过」,规范轴「不通过」——**提权脚本里有一条可稳定复现的本地提权到 root 的路径**,三个前提我逐一亲手核实过:登记目录 `/Library/Logs/DiagnosticReports` 对一个用户组可写(本机账号在该组);普通用户能给 root 文件建硬链接(用 `/etc/hosts` 试过);首版脚本以 root 身份「移进废纸篓再按路径改归属」,改到的是 inode 本身。于是任何以用户身份运行的程序,都能把 `/etc/sudoers` 的硬链接伪装成过期报告放进去,等用户为一次正常清理输密码后接管它。改成两段式后堵上(链接数不为 1 一律不碰;核对与改归属只在 root 私有的暂存目录里做;进废纸篓由用户自己做)。教训写进了 CODING_STANDARDS 新增的「提权纪律」四条与 ADR-0012 的「实施补充」。
- 第二轮:两轴均「有条件通过」,确认提权路径已堵上。余下:调用方环境原样进 root 脚本(内建命令可被导入的同名函数顶替)→ 脚本第一句在干净的环境里重跑;同名条目二次进暂存目录会覆盖 → 不碰;放回原处失败会谎报「没动」→ 回传 `not-restored`;自测鉴别力(评审在临时副本弄坏 19 处,9 处自测照绿)→ 做成仓库里的变异检查脚本,它一跑就抓出自测里两条蒙混过关的用例(重建夹具后忘了重写清单文件,脚本每次都停在更早的一步)。
- 第三轮:规范轴「不通过」——**我在脚本里清环境太晚**:系统脚本在运行复核脚本之前先起一个外层 shell 解释命令,那一步就带着调用方的环境(评审实测:预置跟踪开关与带命令的提示符变量,在复核脚本第一句之前命令已执行)。正解挪到应用侧(通道进程给最小环境),脚本那句重跑保留为第二道;另补齐五条没钉住的规则。需求轴「有条件通过」,条件同是这五条。两位评审都写明:补完跑两个脚本自证即可,不必再审——补完后自测 172 / 1579、变异 38 全如预期。

**实施时自己拍的默认项(评审逐条判过,均在票面 / 方案授权范围内)**

1. 系统级已知条目归「可安全清理」档(方案:认识的归安全档)。要改成默认不勾,是一处档位的事。
2. 每个过期的崩溃报告文件各成一条候选(不聚合成「目录级一条」):删前复核逐文件有效;副作用是过期报告多时「系统级」组会有很多行。
3. 删前复核(只读)先于授权请求:系统级条目全被复核挡下时不弹密码框。
4. 复核脚本对含制表符的路径不写结果行(应用侧的探测与通道两侧也都不收这种路径)。
5. 自测开关四个,只在非 root 生效,root 运行时见到即整批拒绝。
6. 「没开始就停了」做成清理阶段的新形态 + 结果卡的一种形态,两页各出一份。
7. 临时清单文件用 `FileManager.removeItem` 删并加了显式的 `swiftlint:disable:next no_remove_item_outside_deletion_gates`(删的是通道自建的临时文件,不是用户数据);收掉空目录用 `rmdir`。
8. `CleanRunner.run` 的返回类型从战报改成 `CleanRunTermination`(`.completed` / `.aborted`);`systemTrash` 允许为 nil(清单里有系统级条目而它是 nil = 按通道不可用报)。
9. 「清空一个废纸篓目录」抽成静态函数以便测试。
10. 被拒的条目先被移进暂存目录再放回原处(净结果不动、原因照报),仍算「跳过」;放不回去的回传 `not-restored`,原因代码另新增 `duplicate`。
11. GLOSSARY「系统级残留」词条改宽(见 GLOSSARY)。

**两段之间的兜底**

- 应用在脚本交接之后、挪进废纸篓之前被杀:文件留在暂存目录,下一次运行、授权通过之后由应用收进废纸篓(暂存目录名当批次名);只记日志,不在结果卡里报。
- 脚本被强杀(SIGKILL)放不回去的:下一次运行时脚本按原名放回登记目录,只认自己名下、放了 10 分钟以上的。
- 被强杀前已改归属的条目,回到登记目录时仍是调用者的属主(极窄的窗口);后果是它此后每次都被属主规则拒掉,留在原处,不会误删。

**没钉住的(写在自测开头;变异检查里单列)**

- 「root 属主的文件被放行」:普通用户建不出 root 属主的夹具。
- 「被信号打断」与「交接失败」共用同一个退出钩子,只测了后一种。
- 自愈放回时不回退属主(见上)。
- 清单被换成命名管道时「是普通文件」的早筛防卡死。
- 改归属、清空暂存目录、交接在 root 下的真实表现。
- root 运行时拒收自测开关(只读代码核过)。
