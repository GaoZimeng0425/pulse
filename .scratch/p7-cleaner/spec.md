# p7-cleaner:清理向 Mole 对齐(范围 + 系统级按次授权)

Status: ready-for-agent(2026-11-26 grill 两轮定案 + 测试接缝已确认;同日拆票 13 张,用户批准)

词汇:GLOSSARY「清理」节(安全白名单 / 通用发现 / 保护名单 / 系统级残留 / 安装包 / 运行时授权 / 全选);决定:ADR-0012(推翻 ADR-0009)、ADR-0013(改写 ADR-0008)、ADR-0010 原样适用。

## Problem Statement

清理页认得太少,系统目录里的东西碰不到。用户点「扫描整台 Mac」,缓存目录 8.9 GB 里只列出 13 项,另有 48 项 2.2 GB 因为不在名单上既不出现、也清不了(2026-11-26 本机实测:Playwright 浏览器 572 MB、dotslash 363 MB、ReactNative 249 MB…)。下载目录里的旧安装包没有入口。卸载一个带系统级组件的应用后,它的后台服务、特权助手继续留在系统目录里开机自启,我们既不列、也删不了。用户的目标是「电脑尽可能干净」,对齐对象是 Mole(475 处清理项,我们约 80 条规则)。

## Solution

- **认得一样多**:名单写长是主体(许可允许直接搬的规则表全量搬,其余照「清哪个位置、什么条件下才清」自己写),通用发现兜名单外的长尾。
- **系统目录也能清**:涉及系统目录的条目在确认清单里标「需要管理员权限」,确认后弹一次系统管理员密码框,做完这一批即止;Pulse 不常驻管理员能力,现有特权助手不动文件。
- **安装包成组**:下载、桌面、Homebrew 缓存里的安装文件列为「先检查」。
- **清干净更省事**:清单加「全选」按钮,连「先检查」一起勾上,仍过确认清单。
- **卸载对齐**:可多选、显示上次使用时间、连带清掉留在系统目录里的残留。
- **删的方式不变**:一律进废纸篓,「清空废纸篓」单独一步。

## User Stories

1. 作为用户,我想要扫描后看到缓存目录里名单之外的条目,这样那 2.2 GB 不会再因为「不认识」而被漏掉。
2. 作为用户,我想要名单上的条目带一句人话说明它是什么、清了会怎样,这样我不用猜。
3. 作为用户,我想要认识的条目自动归到「可安全清理」,这样「一键清理安全项」能一次带走它们。
4. 作为用户,我想要通用发现里不认识的条目只归「先检查」、不被自动勾上,这样不会在我没看过的情况下被清走。
5. 作为用户,我想要通用发现只出现在缓存、日志、应用数据里的缓存子目录这三处,这样它不会伸手到我的文稿和进行中的工作。
6. 作为用户,我想要正在运行的应用的缓存被跳过,这样不会因为清理让应用出错或要我重新登录。
7. 作为用户,我想要密码管理器、密钥、公司安全软件这类东西永远不出现在清单里,这样我不可能误清它们。
8. 作为用户,我想要知道 Mole 在通用扫描上踩过的坑(日历缓存、壁纸缩略图、接力剪贴板、编译模型缓存)已经被排除,这样不必替它再踩一遍。
9. 作为用户,我想要清单上有一个「全选」按钮,这样想清干净时点两下就够,不用逐项去点几十条。
10. 作为用户,我想要「全选」之后仍然看到确认清单,这样最后还有一次过目的机会。
11. 作为用户,我想要「全选」不被记住,这样下次扫描仍然默认全不勾。
12. 作为用户,我想要在用保护对「全选」同样生效,这样正在被使用的项目产物不会被勾上。
13. 作为用户,我想要扫描后看到系统目录里可以清的东西(过期的系统日志与崩溃报告、可重建的系统缓存、程序已不存在的系统服务),这样系统目录不再是死角。
14. 作为用户,我想要系统级条目在确认清单上标明「需要管理员权限」,这样我提前知道会弹密码框。
15. 作为用户,我想要确认之后只弹一次系统密码框,这样一批里的多个系统级条目不用反复输密码。
16. 作为用户,我想要取消密码框时这一批都不动、勾选保留,这样「取消」就是字面意思。
17. 作为用户,我想要系统级条目也进废纸篓、能在 Finder 里找回,这样清错了有退路。
18. 作为用户,我想要系统级条目进废纸篓后归我所有,这样「清空废纸篓」和 Finder 都能正常处理它。
19. 作为用户,我想要移走一个开机自启的服务时被告知「已在运行的后台进程重启后停止」,这样我不会以为它已经停了。
20. 作为用户,我想要授权失败或某个条目被跳过时如实看到原因,这样不会以为已经清掉了。
21. 作为用户,我想要系统级条目出现在清理历史里(去向、是否用过管理员权限),这样事后能追溯。
22. 作为用户,我想要密码框出现之前已经在确认清单里看过将移走哪些系统级条目,这样密码框写不清的内容我有地方核对。
23. 作为用户,我想要总览上有「系统级」和「安装包」两张模块卡,这样一眼看到这两块各能回收多少。
24. 作为用户,我想要扫描后看到下载、桌面、Homebrew 缓存里的旧 dmg、pkg,这样不用自己去翻。
25. 作为用户,我想要安装包归「先检查」、默认不勾,这样我不会顺手清掉还想留的安装包。
26. 作为用户,我想要安装包进废纸篓,这样拿错了能找回。
27. 作为用户,我想要 iCloud 云盘、邮件、聊天软件目录里的安装包不被碰,这样不会把云端文件一起删掉。
28. 作为用户,我想要项目产物认得和 Mole 一样多的目录种类,这样 Python 工具链缓存这类产物不再漏掉。
29. 作为用户,我想要 7 天内有活动的产物默认不勾、含部署密钥或嵌套代码仓库的目录被拒绝,这样「全选」也不会清掉正在用的或有要紧内容的东西。
30. 作为用户,我想要在应用页一次勾选多个应用一起卸载,这样不用一个个来。
31. 作为用户,我想要看到每个应用上次使用时间,这样判断能不能删。
32. 作为用户,我想要卸载时看到应用留在系统目录里的残留(后台服务、特权助手、输入法),并标明需要管理员权限,这样卸载后系统目录里不再留东西。
33. 作为用户,我想要装在系统输入法目录里的应用也出现在卸载清单里,这样输入法也能从这里卸。
34. 作为用户,我想要卸载时个人数据仍然默认不勾,这样不会顺手清掉账号和本地数据。
35. 作为用户,我想要空间地图上的「可清理」角标只标名单担保过的块,这样地图不会给说不出用途的块暗示可删。
36. 作为用户,我想要 AI 助手经 MCP 清理时仍然只能清安全档、仍要我在应用里确认,这样权限扩大不会绕到我看不到的地方。
37. 作为用户,我想要清理页不因为认得更多而变慢,这样扫描和出清单仍是现在的手感。
38. 作为用户,我想要名单扩充是逐批装上、每批都能用,这样不用等全部做完才变干净。

## Implementation Decisions

**规则表扩充(主体)**
- 开发工具规则、应用缓存知识库、项目产物规则三张表逐条补齐。许可允许直接搬的规则表(MIT)全量搬,逐条注明出处;来源是 GPL 的只借「清哪个位置、什么条件下才清」,零搬码;重叠条目合并成一条。
- 项目产物补齐对齐对象认而我们没有的目录种类(Python 工具链缓存、Gradle 本地目录等),并补三类拒绝:含部署密钥、含嵌套代码仓库、目录内有被 git 跟踪的文件;7 天内有活动的产物默认不勾。
- 每条带条件的条目把条件写进规则(超过 N 天才清、工具在运行就跳过),不是只写路径。

**通用发现(兜底)**
- 新增一个纯值判定,与卸载残留检测同形:输入扫描结果、家目录、正在运行的应用集合、安全白名单命中的路径、保护名单;输出候选。只管三处:缓存目录、日志目录、应用数据目录里名字明确的缓存子目录。
- 命中安全白名单的条目不重复产出(以规则表为准);其余一律「先检查」,带「未识别」条目标志(GLOSSARY「条目标志」),归入现有分组,不新开分组。
- 放着进行中工作的临时目录(如 `/private/tmp`)不进通用发现,只在规则表里按工具点名。

**保护名单**
- 核心层常量单出处,三类:路径(密码与密钥、日历缓存、壁纸缩略图、接力剪贴板近期条目、编译模型缓存)、软件类别(端点防护、设备管理、企业组网)、正在运行的应用(由在用判定动态给出)。动态部分不缓存。

**系统级**
- 规则表新增系统级一族,带「需要管理员权限」条目标志与年龄条件(日志与崩溃报告沿用对齐对象的 7 天阈值)。范围:过期的系统日志与崩溃报告、可重建的系统缓存、程序已不存在的系统服务与启动项、卸载时留在系统目录里的东西。系统统一日志库不登记。
- 新增分组「系统级」与「安装包」;分组枚举的组名、组序、是否按所有者分组的穷举表态同步更新。

**运行时授权**
- 新增一个可替换接口「把系统级条目移进废纸篓(需要授权)」:输入是确认清单里的系统级条目与调用者身份,输出逐项结果(已移 / 跳过及原因 / 授权被取消 / 通道不可用)。
- 真实实现:经系统管理员授权运行随应用分发的复核脚本。脚本只接受清单文件里的条目,逐条按登记过的路径形状复核(前缀、拒符号链接、拒 `..`、属主、年龄条件),移进废纸篓下的专属子目录并把归属改为当前用户,逐项回传结果。
- 编排:确认清单含系统级条目时,先弹授权;取消则整批不动、勾选保留;授权通过后先做系统级、再作用户态条目,逐项如实报。系统服务类条目只移走文件。
- 现有特权助手不改动。

**全选**
- 计划生成处新增第二种预设「全选」:全部非在用条目(含「先检查」、含系统级);不记忆;仍走确认清单。「一键清理安全项」不变。

**安装包**
- 新增匹配:下载、桌面、Homebrew 缓存三处下的 dmg、pkg、mpkg、iso、xip;归「安装包」分组,档位「先检查」;去向废纸篓。

**卸载**
- 应用清单加收系统输入法目录;支持多选;显示上次使用时间(取不到显示「未知」)。
- 残留探测扩到系统目录(后台服务与启动项、特权助手、输入法、收据声明的系统路径),这些行标「需要管理员权限」;个人数据默认不勾不变。卸载里的系统级条目走同一个运行时授权接口。

**不动的部分**
- 删除去向(废纸篓 → 清空废纸篓)、删前复核、在用保护、排除目录、MCP 清理工具(只安全档 + 应用内确认单)均不变。
- 空间地图「可清理标记」只认安全白名单命中的块。

**界面**
- 总览加「系统级」「安装包」两张模块卡,排在「卸载残留」之后,废纸篓卡仍最后;构成条不新增分段,按各自档位归入现有段。「全选」按钮放在全部清单页页头。动手前先补 DESIGN.md 令牌表,页面规格写在该页代码旁。

## Testing Decisions

好的测试只断言外部行为:给进去什么(假目录树、假进程活动、假授权接口)→ 出来什么(候选、档位、计划、逐项结果),不断言内部怎么算。不碰真盘、不弹密码框、不真的提权。全量检查由用户发起。

测试接缝(2026-11-26 用户确认,共四处):
1. **「扫描树 → 候选清单」**(现成):新名单条目、通用发现、安装包、系统级条目的「列不列、进哪个档」全在这里测,用夹具目录树;在运行应用、保护名单作为输入注入。先例:`JunkRuleTableTests`、`AppCacheCatalogTests`、`OrphanLeftoversTests`、`CleanableGroupTests`。
2. **计划生成**(现成):「全选」含先检查与系统级、不含在用项、不记忆;一键清理安全项不受影响。先例:`CleanPlanTests`、`CleanInUse` 相关用例。
3. **「系统级条目移废纸篓(需授权)」接口**(唯一新增接缝):自动测试用假实现,断言收到的路径集合与取消时的整批不动;真实提权路径不进自动化测试(同废纸篓执行器纪律)。先例:`CleanerModelTests` 的假执行器套路、`UninstallModelTests` 的 spy。
4. **复核脚本的脚本自测**(现成模式):不提权、对夹具路径跑校验(哪些形状放行、哪些拒绝、归属改写、逐项结果),挂进全量检查的脚本自测一步。先例:`scripts/test-gc-build.sh`。

登记完整性测试不变:每条内置规则至少一个正例,新增不写用例过不了测试;分组枚举的组名 / 组序 / 按所有者分组有结构性断言(`MetricTabCleanerAxisTests` 套路)。卸载的多选与上次使用时间走卸载模型的假执行器。

## Out of Scope

系统维护(刷新 DNS、修权限、压缩数据库等)、给应用去掉 Intel 部分、空间地图里直接删、系统统一日志库、本地快照、iCloud 云盘 / 邮件 / 聊天软件目录里的安装包、安装用 zip、「清完自动清空废纸篓」开关、常驻的特权删除通道、给现有特权助手加删除能力、`/private/tmp` 进通用发现、搬运 Mole 的代码、自动或定时清理(永久立场)。

## Further Notes

**定案(2026-11-26 grill 两轮,用户逐条拍板)**
- 对齐范围:清理、项目产物、卸载(含系统目录残留)、安装包四块;维护、瘦身、地图直删不在这轮。
- 认得范围:名单写长(主体)+ 通用发现(兜底);通用发现只管三处;认识的「可安全清理」,其余「先检查」。
- 权限:每次清理到系统级那一步授权一次,不常驻,助手不动文件。
- 删的方式:一律进废纸篓,清空废纸篓单独一步。
- 清单加「全选」;安装包只找下载、桌面、Homebrew 缓存。
- 公司安全软件永不列出;正在运行的应用跳过;系统级范围与对齐对象借管理员权限做的那几类一致,统一日志库不动。
- 卸载页做多选和上次使用时间;「默认保留个人数据」不做(残留默认不勾已等价)。
- 测试从四处接缝下手(见上)。

**默认项(未单独拍板,过目时可改)**
- 新分组排在卸载残留之后;通用发现的条目归现有分组、不新开。
- 「全选」在全部清单页页头;取消授权 = 整批不动、勾选保留。
- 系统级条目移进废纸篓专属子目录并改归属为当前用户;系统服务类只移走文件。
- 安装包不收 zip、不设年龄门槛;系统级日志与崩溃报告 7 天阈值。
- 地图「可清理标记」只认名单命中的块;MCP 清理工具不变。
- 「调工具自带的清理命令」型条目(对齐对象的开发工具里有几十处,如让工具自己回收缓存)排在「删目录」型之后单独一批,档位「先检查」。
- 「清完自动清空废纸篓」开关暂不做。

**体量与分批(交付顺序,内部安排)**
- 对齐对象 475 处清理项对 80 条规则,分批交付、每批可装可用。
- 第一批(本机先见效):运行时授权 + 复核脚本 + 系统级分组;通用发现 + 保护名单 + 全选;安装包;许可友好的规则表全量搬运;卸载页多选 / 上次使用时间 / 系统级残留 / 输入法。
- 之后按对齐对象的类别逐类自己写(应用缓存 → 用户级 → 开发工具 → 系统级),最后是命令型条目。
