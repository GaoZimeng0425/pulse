# P1:历史 + 基础传感器(历史页 / 磁盘·网络·电池卡 / 告警 / dev server / 三个小件)

Status: ready-for-agent

## Problem Statement

Pulse 的回答停在"现在":弹窗和主窗口只能告诉我**此刻**谁在吃 CPU。昨晚那波卡顿、上周末哪个项目烧了一下午、这周流量走了多少,一律无从查起——重启一次连孤儿进程的归因都全部蒸发,一切从猜开始。磁盘容量活动监视器和 Finder 各说各话(裸 statfs 在 APFS 上不可信);可清除空间、本地快照这些"空间去哪了"的答案散落在系统各处;电池健康度要去系统设置翻;被遗忘的 dev server 和孤儿进程一样,只有撞见了才知道。而常驻采样本身还有约 2% 单核的成本没有兑现优化承诺。

## Solution

P1 给 Pulse 装上时间维度和机器维度。**历史管线**把组级负载与系统级磁盘/网络/内存按分钟卷积落库(GRDB;分钟表留 7 天、小时表留 30 天),主窗口新增"历史"页按指标 × 时间范围回看;出生登记持久化,重启后孤儿归因不丢。**三张系统卡**按调研钉死的算法接入 popover 与窗口的 tab 体系:磁盘卡 = 容器级容量(petal 对账算法,与 Finder 同口径)+ 可清除空间 + 读写吞吐(IORegistry 内核账)+ 本地快照列表;网络卡 = 内核接口计数差分(带三件防御)+ 物理网卡自动选择(VPN/OrbStack 虚拟接口降级)+ Today/7 天累计;电池卡 = 事件驱动 + 健康度/循环数 + 功率。**告警引擎**内置五条预设规则走系统通知,点开直达对应视图,迟滞防抖。**dev server 卡**盘点被遗忘的开发进程,闲置 24 小时提醒、确认后停止。**三个小件**:菜单栏徽标可配置(默认 CPU+RAM 不变)、常驻采样成本压到约 0.1%、诊断报告一键复制。全程本地无网络,零新系统权限。

## User Stories

1. 作为 Mac 用户,我想让 CPU/内存/网络/磁盘的使用历史落盘保存,这样重启 app 甚至重启电脑后仍能回看之前的负载。
2. 作为排障用户,我想在主窗口新增的"历史"页里选指标(系统负载/CPU/内存/网络/磁盘)看走势,这样按问题类型切视角。
3. 作为排障用户,我想选时间范围(近 1 小时 / 24 小时 / 7 天 / 30 天),这样既能看刚刚的细节也能看这个月的趋势。
4. 作为排障用户,我想让近 7 天有分钟级明细,这样"昨晚十点那波卡顿"能定位到分钟。
5. 作为长期用户,我想让 30 天数据按小时聚合保留,这样历史库不会无限膨胀。
6. 作为多项目开发者,我想让所有组(不只最忙的)都被记录,这样此刻安静的项目过去的高负载也能查到。
7. 作为排障用户,我想让孤儿进程的归因在重启后依然成立(出生登记落库),这样"重启后又变回无名孤儿"的烦恼彻底消失。
8. 作为谨慎的用户,我想让 app 没运行的时间段在历史图上留空而不是补零,这样不会把"没记录"误读成"没负载"。
9. 作为笔记本用户,我想看今天/近 7 天的网络累计流量,这样知道流量花在哪、和运营商账单对得上。
10. 作为 Mac 用户,我想让历史查询不卡界面,这样翻历史时窗口依旧跟手。
11. 作为长期用户,我想让过期数据自动清理(分钟 7 天 / 小时 30 天),这样不用手动管库。
12. 作为 Mac 用户,我想看与 Finder 一致的容器级剩余/已用容量,这样两边数字不打架。
13. 作为空间紧张的用户,我想看"可清除"空间是多少,这样理解为什么系统喊满其实还有余地。
14. 作为较真的用户,我想看各卷明细与"其他卷"差额,这样容量对得上总账。
15. 作为开发者,我想看系统读写速率走势,这样知道是不是构建在磨盘。
16. 作为 Time Machine 用户,我想列出本地快照及其占用,这样知道快照偷偷吃了多少空间。
17. 作为 Mac 用户,我想在弹窗和主窗口都能切到磁盘页,这样两个入口体验一致。
18. 作为 Mac 用户,我想看实时上/下行速率,这样知道现在有没有东西在偷偷传数据。
19. 作为 corplink VPN + OrbStack 用户,我想让速率统计自动落在物理网卡上,这样虚拟接口不会让数字翻倍或归零。
20. 作为 MacBook 用户,我想看电量、充电状态和剩余时间,这样不用点电池图标。
21. 作为 MacBook 用户,我想看电池健康度和循环次数,这样知道电池老化程度。
22. 作为 MacBook 用户,我想看当前功率(充电/放电瓦数),这样知道插电时是什么在大量耗电。
23. 作为 MacBook 用户,我想让"接着电但不充"显示为"优化充电已介入"而不是故障,这样不会被吓到。
24. 作为可能换台式的用户,我想让没电池的机器自动隐藏电池页,这样不会出现空白卡。
25. 作为不想盯盘的用户,我想有五条开箱即用的告警规则(系统负载/组 CPU/新组内存/磁盘剩余/dev server 闲置),这样该提醒的都会提醒。
26. 作为嫌吵的用户,我想在设置里逐条开关告警并修改阈值,这样告警跟着我的耐受度走。
27. 作为用户,我想让告警走系统通知中心,这样不在 Pulse 窗口也能收到。
28. 作为用户,我想点开告警通知直达主窗口的对应视图,这样从提醒到定位只有一步。
29. 作为在意体验的用户,我想让通知授权只在首次开启规则时请求、拒绝后降级为应用内提示,这样不被打断也不丢功能。
30. 作为被通知风暴伤害过的用户,我想让告警有迟滞与冷却期,这样读数在阈值附近抖动不会连环轰炸。
31. 作为开发者,我想让卡片列出在跑的 dev server(闲置时长/内存/监听端口),这样遗忘的进程一目了然。
32. 作为开发者,我想让"全部停止"必须经过确认且绝不自动杀,这样永远不会误伤。
33. 作为用户,我想在设置里配置菜单栏徽标(1–3 槽,每槽从 CPU/RAM/磁盘剩余/网络速率中选),默认保持 CPU+RAM 不变,这样菜单栏听我的。
34. 作为在意常驻成本的用户,我想让常驻采样降到单核约 0.1%,这样监视器本身不再是负载。
35. 作为报 bug 的用户,我想一键复制诊断报告(版本/系统/采样统计/最近日志),这样反馈问题不用手拼信息。
36. 作为合盖用户,我想让唤醒后的第一轮差分作废(清基线),这样唤醒后不会出现一根巨大尖刺。
37. 作为忠实用户,我想让读失败的传感器卡显示占位或上次好值而不是崩溃/伪数,这样一张卡坏了不拖垮整个 app。

## Implementation Decisions

- **架构(ADR-0004,已写)**:引入薄 `SensorProvider`(cadence:heartbeat / every(seconds:) / onEvent + snapshot + lastGood)+ 单一调度器 actor;心跳型指标(CPU/内存/网络吞吐)留在现有 Sampler 循环不拆。不搬 stats 的 Reader 基类(DB 焊在基类 / callback 链拖远程与 Widget / config.plist 运行时声明 / 每 Reader 一个定时器,四点都不要)。
- **存储**:GRDB(SwiftPM,MIT)替代手写 libsqlite3;库文件放 `~/Library/Application Support/Pulse/history.sqlite`,WAL 模式。每 60 秒把内存环形缓冲卷积进分钟表;5 秒原始值永不落盘。表结构(设计文档 §5 草案 + 本轮修订):
  ```sql
  sample_min  (ts, group_id, cpu_avg, cpu_max, mem_max, procs, disk_r, disk_w)  -- 留 7 天;disk 两列本阶段恒空(见下)
  sample_hour (同构)                                                             -- 留 30 天
  system_min  (ts, load_avg, load_max, net_rx, net_tx, disk_read, disk_written) -- 系统级增量,留 7 天
  system_hour (同构)                                                             -- 留 30 天
  lineage     (pid, uniqid, parent_chain, argv, cwd, first_seen)                 -- 出生登记持久化
  groups      (group_id, name, category, project_root)                           -- 展示元数据缓存
  ```
  留存清理随每日首次 rollup 顺带执行;"今天/7 天"网络累计 = 对 system 表 SQL 聚合,日界为当地零点。所有组都记(~80 组 × 1440 行/天,SQLite 无压力)。app 未运行 = 无行,历史页留空不补零。
- **每组磁盘读写不记(本轮拍板)**:读它需要每进程一次 rusage 系统调用(~850 次/轮),与采样成本优化直接冲突,且 P1 无消费界面。schema 保留列位,将来与采样优化一起做(每进程 rusage 是磁盘归因到组的唯一来源,推迟≠放弃)。
- **磁盘吞吐改走 IORegistry(本轮修正)**:每轮一次读块存储驱动的字节累计计数(stats 同款,内核账——短命进程与内核回写都在),差分带计数回退/elapsed 有限两件防护;放弃原 rusage 求和方案(每进程成本 + 短命进程漏账 + 页缓存口径两不靠)。**工单 0 探针**:若本机 NVMe 未在 IORegistry 露出统计,回退 rusage 求和并降到 30s 低频档。
- **三卡算法(全部经调研钉死,MIT 来源须在文件头注明)**:
  - 磁盘卡:容器对账(statfs('/') → 容器号归约 → getmntinfo 同容器过滤 → 每卷 getattrlist 精确已用 → 差额记"其他卷");可清除 = 两种可用容量官方口径之差;快照列表 fs_snapshot_list(TM 前缀识别);不变式"各卷之和 + 其他卷 == 容器总量"做成单测。
  - 网络卡:NET_RT_IFLIST2 差分 + 三件防御(首读置零/负值钳零/重连跳变丢弃)+ 主接口选择(SCDynamicStore 主接口 → 虚拟前缀降级 → getifaddrs 回退);不做 stats 的 VPN 除二 hack(选定物理口后不需要)。网络吞吐是心跳型,进 Sampler 循环(每轮一次 sysctl,便宜)。入向死表回退:主接口入向计数为死表时改读在场活口(累计入向字节最多者)。
  - 电池卡:IOPS 通知事件驱动不轮询;健康度走 IORegistry 容量回退链(arm64 分支);功率 = 电流×电压(SMC 精确功率是 P2);NotChargingReason 映射"优化充电已介入";设计容量为 0 钳 1 防除零;无电池机器整页隐藏。
- **工单 0 = 三项探针**(先于三卡实现):①purgeable 两口径(CSDiskSpace vs CFURL 两 key 差值)在 macOS 26 的数值对照;②fs_snapshot_list 是否仍免 root 可列;③IORegistry 块驱动统计对本机 NVMe 的覆盖。结果写回调研文档 §5。
- **卡片接入**:三卡进现有 MetricTabModel tab 体系(popover + 主窗口同构);读缺失显示占位不伪造,lastGood 降级;图表用 Canvas(与 P0.6 同决策),复用 MetricAccent 令牌;历史页近 1 小时视图读分钟表,现有卡片实时小图(内存环形缓冲)不动。
- **告警**:纯规则引擎(匹配器 × 指标 × 阈值 × 持续时长 × 冷却期,进入需连续 3 次超阈、退出需连续 6 次低于阈值−20%);五条预设(系统负载 >70% 持续 5min / 组 CPU >300% 持续 10min / 新组 mem >2GB / 磁盘可用 <20GB / dev server 闲置 >24h),设置页逐条开关+改阈值;系统通知走薄封装,点开经现有窗口导航路由到对应视图;授权在首次开启规则时请求,拒绝则应用内提示。
- **dev server finder**:argv 分类器是纯函数,直接吃现有进程快照(零新采集成本);只有候选进程才做端口扫描(PROC_PIDLISTFDS socket 信息);"闲置"标签 = 最近 10 分钟 CPU≈0;卡片在主窗口总览页(popover 不放);全部停止走现有确认流。
- **菜单栏徽标可配置**:设置新增"菜单栏"页;1–3 槽、每槽四选一(CPU%/RAM%/磁盘剩余/网络速率);渲染器参数化,默认 CPU+RAM 与现状逐像素一致;网络徽标紧凑上下行格式,放不下降级为只显示下载。
- **采样成本优化**:argv 进程终身不变、cwd 罕变 → 出生登记时读一次并缓存,活链扫描的每进程调用从 ~6 次降到 2–3 次;验收口径 cputime÷etime,目标常驻 ≈0.1% 单核。
- **唤醒处理**:所有差分型指标(网络计数、磁盘吞吐、CPU tick)监听唤醒通知,唤醒后第一轮作废/清基线。
- **诊断报告**:纯文本拼装(app 版本/macOS/机型/采样统计/最近日志尾部)进剪贴板;日志从现有 LogService 文件读取。
- **日志**:新埋点按"过渡非轮询"惯例——采样轮失败状态迁移、告警触发/恢复、rollup 失败、探针结论,不逐轮打点。
- **移植代码纪律**:petal/stats 的翻译文件头注明来源与 license(§12 既定)。

## Testing Decisions

- **缝(用户已确认)**:每类传感器的 OS 边界各一条薄原始读数协议,缝上全纯逻辑——磁盘容量源 / 磁盘吞吐源 / 网络计数源 / 电池源 / 端口扫描源 / 通知发送,共六条新缝;`ProcessSource` 等旧缝不动。历史库**不设缝**:GRDB 直接对真库测(内存/临时目录库),rollup、留存清理、 lineage 持久化、聚合查询都打真 SQLite。UI 层(历史页/卡片/徽标设置页)不单测,走 SwiftUI 预览 + 真机验收(P0 既定)。
- **纯逻辑测试清单**:容器对账与"其他卷"兜底(不变式:各卷之和 + 其他卷 == 容器总量);purgeable 差值;吞吐差分与回退防护;网络差分三件套 + 虚拟接口降级(注入假链路状态);电池健康回退链 + NotChargingReason 映射 + 除零防护;告警规则的阈值/持续/迟滞/冷却状态机(注入时钟);dev server argv 分类器 + 闲置判定(注入时钟);徽标槽位配置映射;rollup 聚合与留存清理(注入时钟)。
- **先例**:CPUDiffer/GroupingEngine 的合成快照测法、SamplingCadence/Scheduler 的注入时钟、GroupCategoryDisplayTests 的样式表完整性断言、petal 自带的容器对账不变式断言(翻译时保留)。
- **纪律**:单测不制造真实 CPU 负载(合成数据优先,真负载只在验收走查用 ≤20 秒少数几核短突发,用后即清)。

## Out of Scope

- 项目可回收产物扫描(§8.1)——本轮拍板推迟,将来单独一期(盘点 or 连删除闸门,到时再议)。
- 每组磁盘读写记录——与采样成本优化捆成一个后续工单。
- P2 全部:GPU / 神经网络引擎 / SMC 温度风扇 / 声音 / 蓝牙电量 / 容器 tab;P3 全部:root helper、每 App 能耗/GPU/网络归因、MCP server、Agents 用量卡。
- SMC 精确电池功率(PPBR/PDTR)——P2 增强项。
- WiFi 详情(SSID/RSSI,要定位权限)、公网 IP 查询——永久不做(违反"全程本地无网络")。
- 历史导出 CSV / 分享。
- 多语言、license 体系、App Store 上架(常砍项)。

## Further Notes

- **交付顺序(已拍板)**:①历史管线(GRDB+rollup+lineage 持久化)→ 历史页 → ②三张传感器卡(工单 0 探针先行)→ ③告警 → ④dev server → ⑤小件(徽标配置/采样优化/诊断报告)。历史先行:网络累计、告警数据、"重启丢归因"收尾都挂在它上面,且第一天就开始积累数据。
- **验收锚点(四条,真机见证)**:①app 跑一晚 + 重启后历史页曲线完整、曾见过的孤儿进程仍归原宿主;②磁盘卡容量/可清除与 Finder 一致,网络速率与 Stats.app 同刻对照一致;③≤20 秒短负载真实触发一次组 CPU 告警且点开跳转正确;④常驻采样实测 ≈0.1% 单核(cputime÷etime)。
- 探针结果可能微调三卡实现细节,回退路径已在实现决策里写死;预估 2–3 个周末。
- 领域术语(告警规则/迟滞/dev server/闲置/容器级容量/可清除空间/本地快照)已入 GLOSSARY.md,规格与工单用语以它为准。
