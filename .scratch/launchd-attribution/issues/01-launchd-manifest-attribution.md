# 01: launchd 真实清单归组——第三方 LaunchDaemon 不再落孤儿

**What to build:** 把归组引擎"后台服务"判定的 launchd 域推断升级(或补强)为真实 launchd 服务清单:进程经三层归属落空、且(出生或现挂)父为 launchd 时,若其可执行路径命中本机 launchd 实际注册的服务程序路径,则归"后台服务"而非"孤儿进程"。现状是纯静态路径前缀名单(`/usr/sbin`、`/usr/libexec`、`/Library/LaunchDaemons` 等,`GroupingEngine.swift` `isLaunchdDomainExecutablePath`),自装在 `/usr/local`、`/opt` 等处的第三方 LaunchDaemon 全部落孤儿。

**Status:** ready-for-agent
**Category:** enhancement

## 为什么现在开(现场证据,2026-10-20)

- 本机全机累计流量第一的进程 `corplink-service`(CorpLink VPN 隧道守护,root,父为 launchd,路径 `/usr/local/corplink/corplink-service`)落孤儿组;VPN 连接期间"孤儿进程"行常年顶着大 ↓↑(5s 差分实测 ↓380 KiB/s ↑178 KiB/s,累计 8.6 GiB),观感严重失真。
- `/usr/local` 有意不算域是评审 S3 的拍板(自装常驻不并入系统后台服务桶,`GroupingEngine.swift:231-233` 注释钉死)。本票**不改这个口径本身**,而是给"确实是 launchd 注册服务"的进程一条真实的判定路径——S3 的本意(一次性用户命令 ssh/python3 不算服务)由"必须命中真实清单"天然保住。
- `GroupingEngine.swift:233` 注释已预告"P1 可升级为真实读取 launchd 任务清单",本票即兑现。

## 方案要点与开放问题

- 清单来源两候选,需探针拍板:
  1. `launchctl print system` / `launchctl print gui/<uid>` 解析输出(权威,含临时加载的服务;但本身是子进程,成本约束见下);
  2. 扫 `/Library/LaunchDaemons/*.plist`、`/Library/LaunchAgents`、`~/Library/LaunchAgents` 的 Program/ProgramArguments(纯文件读,无子进程;漏掉非常规目录注册的服务)。
- **成本红线**:清单读取不得进采样热路径。launchctl 也是子进程,若选它必须低频(分钟级)+ 缓存失效策略(服务注册变化不频繁);plist 扫描同样按分钟级缓存。归组引擎是纯函数,清单以注入的 `Set<String>`(或类似)进入配置,不在引擎内做 IO。
- 匹配口径:命中判定按可执行路径全等还是前缀?服务 program 可能带参数、可能是相对解释器脚本——探针时用 corplink-service 实例钉死。
- 相关观察(不承诺本票修):Bitdefender `BDLDaemon` 路径含 `.app/Contents/MacOS/`(`/Library/Bitdefender/.../BDLDaemon.app/...`),被 App 归属第一层抢先收进名为"BDLDaemon"的 App 组,launchd 清单救不了它——严格 `.app` 全盘口径与 launchd 服务的判定顺序问题是否动,留给 triage 时拍板,不默认扩票。

## 验收

- [ ] `corplink-service`(或任一 `/usr/local`、`/Library/<厂商>/` 下的第三方 LaunchDaemon)在真机上归"后台服务",孤儿行不再被 VPN 隧道流量顶榜
- [ ] S3 语义回归:launchd 拉起但不在清单里的一次性命令(如 `/usr/bin/ssh`)仍不归后台服务
- [ ] 既有归组测试全绿;新增清单命中 / 未命中 / 清单不可用(读取失败退回现静态前缀名单)三档单测
- [ ] 清单读取有低频缓存,采样热路径零新增子进程

## Agent Brief

**Category:** enhancement
**Summary:** 让归组引擎用本机 launchd 真实注册的服务程序路径判定"后台服务",使 `/usr/local`、`/Library/<厂商>/` 等非标准驻地的第三方 LaunchDaemon(如 corplink-service)不再落"孤儿进程"组。代码注释引用本票写全名 `launchd-attribution/01`。

**Current behavior:**
归组引擎 `GroupingEngine`(PulseCore 包,纯函数)对每个进程依次做 App 归属 → 项目归因 → 父链上溯 / 出生登记回查;全部落空进入兜底三分类。其中"后台服务"判定要求两条同时成立:(a)出生时或现在父为 launchd;(b)可执行路径命中静态前缀名单 `isLaunchdDomainExecutablePath`(/usr/sbin、/usr/libexec、/Library/LaunchDaemons|LaunchAgents、/System/Library、/Library/SystemExtensions、/Library/PrivilegedHelperTools、/Library/Developer、任意 ~/Library/LaunchAgents)。`/usr/local`、`/opt/homebrew` 有意不在名单(评审 S3:自装常驻不并入系统后台服务桶)。后果:在 launchd 正式注册、但程序驻地非标准的第三方守护全部落孤儿。真机实证见上方 triage 记录。

**Desired behavior:**
- 引入领域概念 **launchd 服务清单**:本机 launchd 当前注册的服务 → 各服务程序可执行路径的集合。兜底分类时,条件 (b) 变为"命中静态前缀名单 **或** 命中 launchd 服务清单";条件 (a) 不变。两者皆不命中 → 孤儿(不变)。
- S3 语义保留:静态名单不加 `/usr/local` 等;只有"确实在 launchd 注册"的程序才经清单归后台服务。由 shell 拉起、不在清单的一次性命令(ssh / python3 等)仍不算后台服务。
- 引擎保持纯函数:清单经 `GroupingConfiguration` 新增字段(可执行路径集合,缺省空集)注入;读取 IO 全在 app 侧 Live 适配器。
- 成本红线:清单读取不进采样热路径。分钟级或更低频刷新 + 缓存;读取失败 / 空结果 → 该轮按空清单处理(退回仅静态名单),归组不中断;失败态按状态沿记日志(transition-not-tick,失败进入 / 变种 / 恢复各记一条,同态静默)。若选用子进程路径,须具备与 nettop 源同级的超时与看门狗纪律。
- 清单来源由实施者探针拍板,两候选:① `launchctl print system` 与 `launchctl print gui/<uid>` 的输出解析(权威、含临时加载服务;本身是子进程);② 扫 /Library/LaunchDaemons、/Library/LaunchAgents、~/Library/LaunchAgents 下 plist 的 Program / ProgramArguments 首项(纯文件读;漏掉非常规目录与临时加载的服务)。拍板条件:至少能让 corplink-service 实例命中;记录两者覆盖差异与成本。
- 匹配口径:可执行路径全等为准;探针核对服务程序为脚本 / 解释器包装、符号链接的情形,若需规范化(realpath)或放宽,写进 ADR。

**Key interfaces:**
- `GroupingConfiguration`:新增 launchd 服务程序路径集合字段,缺省空集 ⇒ 行为与现在逐位一致。
- `GroupingEngine.isLaunchdDomainExecutablePath`:保留为静态兜底;清单命中判定与之并列(或在兜底分类处组合),判定只保留一份实现。
- app 侧新增 launchd 清单源:薄源协议 + Live 实现 + 测试用合成 / inert 实现,沿 SensorProvider 与薄源协议(ADR-0004)惯例,cadence 低频;装配处(现为 MonitorAssembly 一类的组装点)把清单接入 GroupingConfiguration。

**Acceptance criteria:**
- [ ] 单测:清单命中 ∧ 父为 launchd → 后台服务;清单命中 ∧ 父非 launchd ∧ 无三层归属 → 与改前结果一致(清单不单独改判);清单未命中 → 与改前逐位一致;清单为空集 → 全部既有归组测试原样通过。
- [ ] 单测:清单读取失败 / 空 → 退回静态名单,无崩溃;状态沿日志只在失败态变化时记录。
- [ ] 真机:corplink-service(或任一 `/usr/local`、`/Library/<厂商>/` 下的 launchd 注册守护)归"后台服务";网络每进程排行里"孤儿进程"行不再被 VPN 隧道流量顶榜。
- [ ] S3 回归:launchd 之下但不在清单的一次性命令仍不归后台服务(以 /usr/bin/ssh 形态的合成夹具钉死)。
- [ ] 成本:采样热路径零新增子进程;清单刷新间隔 ≥ 60s 或事件驱动,有测试钉住"刷新间隔内重复取用不触发读取"。
- [ ] 清单来源选型与匹配口径写进 docs/adr/(新 ADR 或 ADR-0004 附录);GLOSSARY 增补"launchd 服务清单"词条。
- [ ] `sh scripts/check.sh` 全绿。

**Out of scope:**
- 改变 App 归属与后台服务的判定顺序(BDLDaemon 类路径含 `.app` 被 App 归属抢先——2026-10-20 triage 拍板维持现状)。
- 把 `/usr/local`、`/opt/homebrew` 加进静态前缀名单(违背评审 S3)。
- 用户可配置的后台服务名单或手动归组 UI。
- 历史管线对已落库 `orphan` 键行的回填 / 迁移:归组变化只影响新写入,存量分钟 / 小时行保持原键。
