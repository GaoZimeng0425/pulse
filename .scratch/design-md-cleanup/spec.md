# DESIGN.md 全量清 + 项目视觉统一

Status: ready-for-agent

来源:2026-11-23 用户在删除空间地图路径栏「回到整卷」后追问「为什么 DESIGN.md
里会有这种东西」,三轮磨想法达成本共识。决策依据见 ADR-0011。

## Problem Statement

写界面的 agent 每次动手前都要读 DESIGN.md。这份文件自称「全部 UI 的唯一视觉
宪法」,实际已经是一本流水账:866 行里约 350 行是某一页怎么画的实现细节,规则
中间夹着日期、工单号和被毙方案的叙述,还有一节「已知偏差」记着没改完的账。读的
人分不清哪些是必须守的规矩、哪些是某一页的历史。同一类控件的规矩埋在页面叙述里
(面包屑的写法夹在空间地图那一段中间),别处要复用时找不到。归属也有错:「服务页」
条目下约 110 行其实是智能体页的内容。

项目也没有真的统一。代码里还留着 6 处旧的系统小字号,菜单栏徽标的警示色直接写
系统橙红,设置侧栏图标砖的 10 个渐变色是写死的数值,同一个右箭头图标用了 10、11、
12、13 四种大小。靠「记账 + 动到再改」管不住:上一轮清字号漏了清理设置页的 2 处,
账上一直没有。

## Solution

DESIGN.md 只回答两件事:全 app 的原则是什么;每个通用界面件长什么样、有哪些
状态、什么时候用。某一页怎么实现,写在该页代码旁的注释里,按统一标准重写,不搬运。

规范里不再有「例外」和「偏差」。原先登记为例外的三条改写成规范条目;没改完的
这次全部改完,并加一条 lint 规则防止再犯。

清完后界面只有几处微调:进程下钻与清理设置页的 6 处文字从 10pt 改到 10.5pt;
菜单栏告警色从系统橙红换成 app 自己的警示色;图标尺寸归到五档。其余外观与行为
不变。

## User Stories

1. 作为写界面的 agent,我希望打开 DESIGN.md 读到的是全 app 的原则和每个通用界面件的规范,以便不翻页面流水账就知道必须守什么。
2. 作为写界面的 agent,我希望规范里没有日期、工单号和被毙方案的叙述,以便读到的是规则本身。
3. 作为写界面的 agent,我希望一条规矩"该进 DESIGN.md 还是该进代码"有一句能判的标准,以便不用每次凭感觉。
4. 作为写界面的 agent,我希望某一页怎么实现写在该页代码旁,以便动那段代码时一定看得到。
5. 作为写界面的 agent,我希望每条规矩只有一个出处,以便不会遇到两处说法打架。
6. 作为写界面的 agent,我希望页面规格是按统一标准重写的简短注释,而不是从文档搬来的大段叙述,以便读得下去。
7. 作为写界面的 agent,我希望有「面包屑」的组件规范,以便任何页面要放层级路径时照同一套做。
8. 作为写界面的 agent,我希望有「搜索框」的组件规范,以便主窗口工具栏和各子页的搜索框长一个样。
9. 作为写界面的 agent,我希望有「勾选框」的组件规范(含组头三态),以便清理页以外需要勾选时不另造一套。
10. 作为写界面的 agent,我希望有「图表悬停读数与浮层」的组件规范,以便历史页、智能体页和空间地图的悬停是同一套做法。
11. 作为写界面的 agent,我希望有「卡头文字按钮」的组件规范,以便卡头上的次要动作在所有页面同一写法。
12. 作为写界面的 agent,我希望有「设置侧栏图标砖」的组件规范,写明渐变底和投影是规范的一部分,以便不再把它当例外。
13. 作为写界面的 agent,我希望「无投影、不描边」写清楚只管卡片和容器的层级,以便既不给卡片加投影,也不误以为图标砖、图表线条、控件轮廓违规。
14. 作为写界面的 agent,我希望规范写明图表怎么分工(环形与折线用系统图表库,高频重画的走势自绘),以便新做图表时不各选各的。
15. 作为写界面的 agent,我希望令牌表只列在用的令牌、每个令牌一句话用途,以便查表时不被长注释淹没。
16. 作为写界面的 agent,我希望图标尺寸有明确的档位和单一出处,以便同一个箭头不会四处大小不一。
17. 作为写界面的 agent,我希望再写出系统小字号时提交就被拦住,以便不统一的东西进不了库。
18. 作为写界面的 agent,我希望代码注释里不再有指向已不存在的 DESIGN.md 条目的回指,以便不被引到空处。
19. 作为使用者,我希望全 app 文字字号只有五档,以便观感统一(进程下钻和清理设置页剩下的小字改到位)。
20. 作为使用者,我希望菜单栏告警色和窗口里的警示色是同一组颜色,以便同一种状态在两处长一个样。
21. 作为使用者,我希望菜单栏告警色在深色和浅色菜单栏下都清楚可读。
22. 作为使用者,我希望设置窗侧栏图标保持现在的样子,以便这次清理不改变我已经认可的观感。
23. 作为使用者,我希望箭头和行内图标大小一致,以便界面不显得东一处大、西一处小。
24. 作为使用者,我希望除了上面列出的几处尺寸与颜色,界面外观和操作都不变,以便这次是"统一"而不是"改版"。
25. 作为使用者,我希望智能体页的规格不再挂在「服务页」名下,以便查某一页的规矩时找对地方。
26. 作为评审者,我希望每一页有一张去向表(原规矩 → 保留在哪 / 新写到哪 / 删,原因),以便核对没有规矩被悄悄弄丢。
27. 作为评审者,我希望文档与注释的改动和代码行为的改动在提交里分得清,以便确认没有夹带行为变化。
28. 作为维护者,我希望有一条决策记录写明「DESIGN.md 只收原则和组件规范」和三个词的定义,以便以后有人问起有据可查。
29. 作为维护者,我希望 AGENTS.md 的规矩与新的分工一致(该读什么、该往哪写),以便以后的 agent 不再按旧写法往 DESIGN.md 加实现细节。
30. 作为维护者,我希望规范里不再有「已知偏差」这类账本,以便规范只描述现在应该是什么。
31. 作为维护者,我希望清完后的 DESIGN.md 明显变短(估算四百多行),以便维护成本下降。

## Implementation Decisions

### 判定法与三个定义

- **原则**:全 app 成立、不提任何页面的规矩(颜色、字号、间距、圆角、层级、
  该做不该做)。
- **组件规范**:一个通用界面件长什么样、有哪些状态、什么时候用;不提它被哪一页
  使用。
- **实现细节**:只对某一屏成立的摆法、交互、文案。
- **判定法**:把句子里的页面名遮掉。还成立 → 原则或组件规范;不成立 → 实现细节。
- **只在一处使用的件再分两种**:通用界面件(换一页也可能用)立组件规范;业务专用
  的图和卡(换一页就没意义)按实现细节处理。
- **通用件(本次新立规范)**:面包屑、搜索框、勾选框(含组头三态)、图表悬停读数与
  浮层、卡头文字按钮、设置侧栏图标砖。
- **业务专用件(按实现细节写进代码)**:空间地图本体、热力墙、走势图、项目大卡、
  会话卡、数字卡排、Hero 卡、模块大卡、废纸篓卡、监听端口卡、风扇卡。

### DESIGN.md 的新结构

- 保留规范要求的开头令牌(颜色、字号、圆角、间距、组件指针)与各节(总览、颜色、
  字号、版式、层级、形状、组件、该做不该做)。
- 组件一节重写为 16 条,每条统一成:一句话用途 → 形态与数值 → 状态与变体 →
  什么时候用。其中 10 条由现有条目重写而来(卡片家族零件、行两档制、状态芯片、
  指标卡两形态、卡片网格、排行列表、药丸页签条、页头、菜单栏徽标、走势图与条形
  图),6 条是新立的通用件。
- 原则层新增或改写四处:层级原则写明只管卡片、容器、弹层,靠底色差分层次;
  图表分工;文字五档的适用范围(图标的尺寸走图标档位);主窗口与弹窗同一套卡片
  组成(传感器明细卡与空间地图只在主窗口,写成规则的一部分)。
- 令牌表:删 6 个已废令牌(删前逐个核过代码确无引用);每个令牌的「用在哪」压成
  一句、不带历史;新增图标档位一组令牌;新增设置图标砖的 10 个渐变色令牌。
- 「已知偏差」整节删除,内容按上面各条归位。
- 全文去掉日期、工单号、被毙方案的叙述;只在「不写原因会被改坏」处留半句原因。
  文件版本号升一级。

### 页面规格的去向(全部重写进代码,不搬运)

- 涉及的页:清理总览页、清理页清单与舒适密度、清理页子页命名、清理设置页、空间
  地图卡、弹窗外壳、主窗口工具栏、传感器卡文案、智能体页的两个子页、服务页。
- 原挂在「服务页」名下的智能体页内容归智能体页。

### 注释重写标准

1. 每条规矩只留一个家,写在它管的那段代码旁边;文件头只放骨架(这页由哪几块
   组成、什么只出现在主窗口或弹窗)。
2. 只写代码本身读不出来的东西:为什么这样做、还会有人再踩的坑、必须和别处一致
   的口径。一眼读得出的数值和颜色不重复写。
3. 不写历史:改过几版、哪天拍板、被毙的方案都不写;想留来历,最多带一个工单号。
4. 代码里已有的同类注释就是它的家,DESIGN.md 那份直接删;两处说法不一致时以
   代码旁为准改齐。
5. 文体跟现有注释一样,简短中文,不写成文档体。

### 代码统一

- **文字字号**:6 处系统 10pt 小字改为 10.5pt,沿用上一轮定过的「10 → 10.5」
  对照(进程下钻 4 处、清理设置页 2 处)。
- **菜单栏徽标警示色**:警示与危险两级取语义令牌;渲染器按传入的外观显式取该
  外观下的令牌值,不依赖渲染环境。
- **图标档位**:五档 9 / 11 / 13 / 16 / 26,单一出处是一个纯值的档位类型,与行
  尺寸、大数字字号同一做法。排序与展开收起的上下箭头 = 9;行内符号(行尾右箭头、
  卡头符号、小按钮里的符号、状态符号、勾选框对勾、页签条图标)= 11;行首类型符号
  紧凑档 = 13、舒适档 = 16(随行两档制);空态大符号 = 26。随容器走的图标(状态
  芯片里的符号、类别图标瓦与设置图标砖里的符号、弹窗图标页签)由所在组件的规范
  给出算法,不归这五档。并入现状:7 → 9;行内的 10、10.5、11、12、13 → 11;
  每应用音量卡的静音按钮由「紧凑 11 / 舒适 13」改为恒 11。约 14 处
  (分档方案 2026-11-23 用户确认)。
- **设置图标砖**:10 个渐变色移入颜色令牌的单一出处;外观不变。
- **lint**:视图代码禁用系统语义字体,文字与图标都写显式字号。

### 规矩与记录

- AGENTS.md 的界面规矩改述为:写或改任何 SwiftUI 视图前先读 DESIGN.md(原则与
  组件规范)和所在页主视图文件开头的页面规格;数值不在令牌表里先补表再写码;
  DESIGN.md 只收原则和组件规范,某一页怎么实现写在该页代码旁的注释里;规范与
  页面规格里已定的样式不得静默改,要改先问用户。
- DESIGN.md「该做不该做」同步改述,删去逐项列举的「已拍板样式」。
- 立决策记录 ADR-0011,定义原则、组件规范、实现细节三个词。

### 行为边界

- 除列明的尺寸与颜色调整外零行为变化。
- 重写页面规格时若发现文档与代码不一致,以代码为准,差异记入去向表交用户,
  不顺手改行为。

## Testing Decisions

- 好的测试只断言外部可观察的结果:徽标位图里告警文字的实际像素颜色等于令牌在该
  外观下的值;图标档位的取值等于约定值;lint 规则对违规写法报错、对合规写法放行。
  不断言内部实现。
- 沿用三个现有接缝,不新增:
  1. **lint**:在现有自定义规则机制里加一条,先例是「删除闸」规则。全仓 lint 通过
     即证明代码里不再有系统语义字体。
  2. **菜单栏徽标渲染器**:在现有宿主测试里加像素断言——深、浅两种外观各渲染一张
     警示徽标,取文字像素与令牌值比对。先例是同文件里已有的徽标渲染与宽度测试。
  3. **图标档位**:新类型是纯值,单测钉死五个取值,先例是行两档制与字号五档的
     防漂移单测。
- 文档与注释不写自动测试:以去向表评审兜底,构建通过即证明注释没有破坏代码;
  外观变化由用户目验。

## Out of Scope

- 图标尺寸以外的图标风格(字重、符号选用)。
- 各页的功能与交互改动。
- 术语表(GLOSSARY)增词:三个文档用词写进决策记录,不进产品术语表。
- 既有代码注释的全量清理:只处理与本次规格重写重叠的部分。
- 菜单栏徽标判定外观的来源(跟随 app 外观)不改。

## Further Notes

- 页面规格的重写按页分给实施子代理并行,各管各的文件;产出须回源核验后才进报告。
- 文档与注释的改动、代码行为的改动分成不同的提交,便于评审。
- 格式依据:Google Labs 的 DESIGN.md 开放规范(各节均为系统级;组件一节只管组件
  原子;对粒度与长度没有规定)。
