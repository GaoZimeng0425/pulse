## Agent Brief

**Category:** enhancement

**Summary:** 清理页族的页面规格从 DESIGN.md 重写进代码注释,逐条交代去向。

**Current behavior:**

五段规格共约 130 行写在 DESIGN.md,夹着日期、工单号、被毙方案与旧值对照;代码里
同时已有大量同义注释(写功能时留下的),个别规矩代码里没有注释。

**Desired behavior:**

按五条标准重写:

1. 每条规矩只留一个家,写在它管的那段代码旁边;文件头只放页面骨架(这页由哪几块
   组成、什么只出现在主窗口或弹窗)。
2. 只写代码本身读不出来的东西:为什么这样做、还会有人再踩的坑、必须和别处一致
   的口径。一眼读得出的数值和颜色不重复写。
3. 不写历史:改过几版、哪天拍板、被毙的方案都不写;想留来历,最多带一个工单号。
4. 代码里已有的同类注释就是它的家,DESIGN.md 那份直接删;两处说法不一致时以代码
   旁为准改齐。与本次重写重叠的旧注释(含文件头)一并按标准改写,不相关的既有
   注释不动。
5. 文体跟现有注释一致,简短中文,不写成文档体。

产出一张去向表:原规矩逐条 → 已在代码何处 / 新写到何处 / 删,原因(代码自明 /
已废 / 历史 / 被新规矩取代)。

通用件的规矩不重写进页面注释,只在去向表标注「归组件规范,票 07 立条目」:
搜索框、勾选框(含组头三态)、卡头文字按钮、安全档芯片的色映射、空态必须给出路。

**Key interfaces:**

- 只改注释。不改任何代码行为、不改用户可见文案、不改 DESIGN.md。

**Acceptance criteria:**

- [ ] 去向表覆盖原五段的每一条规矩,每条有明确去向
- [ ] 改动只涉及注释行(机械核对:去掉注释后,改前改后的代码逐字相同)
- [ ] 清理页各视图文件头有页面骨架说明
- [ ] 全量检查通过

**Out of scope:**

- 清理页的功能与交互
- DESIGN.md 的改写
- 通用件规范的正文(票 07)
