# 03: 菜单栏徽标警示色取令牌

**What to build:** 菜单栏徽标的警示与危险两级不再直接写系统橙、红,改取 app 的
警示色与负面色令牌(各带深浅两套);渲染时按传入的外观显式取值,深浅菜单栏下
都清楚可读。

**Blocked by:** None (can start immediately).

**Status:** done(代码 2026-11-23 完成;合入与用户目验归票 09)

## Agent Brief

**Category:** enhancement

**Summary:** 徽标警示 / 危险两级改取语义颜色令牌,按传入外观取值,加像素单测。

**Current behavior:**

徽标渲染器按强调级取色:普通 = 墨色(随外观取黑或白),警示 = 系统橙,危险 =
系统红。渲染器已接收外观参数并据此定墨色,但橙、红是系统动态色,按渲染时环境的
实际外观解析,不保证与传入外观一致。现有测试覆盖组合、缓存键、宽度、高度,
没有颜色断言。规范原将这一处登记为「待验证后换令牌」的例外。

**Desired behavior:**

- 警示取 `{colors.state-warning}`,危险取 `{colors.state-negative}`。
- 渲染器用**传入的**外观决定取深值还是浅值,不依赖渲染环境。
- 像素单测:深、浅两种外观各渲染一张警示徽标与一张危险徽标,取数值文字的像素
  颜色,与令牌在该外观下的值比对(取最饱和像素以避开抗锯齿边缘)。
- 徽标尺寸、缓存键、组合行为不变。

**Key interfaces:**

- 渲染器的取色函数可增加外观参数。
- 颜色令牌需提供「按外观取定值」的入口(现有「深浅两值合成动态色」的反向)。

**Acceptance criteria:**

- [ ] 渲染器代码里不再出现系统橙、红
- [ ] 像素单测覆盖深 / 浅 × 警示 / 危险四张并通过
- [ ] 徽标现有测试全绿(尺寸、缓存键、组合行为不变)
- [ ] 用户目验:深、浅菜单栏下告警徽标颜色清楚可读

**Out of scope:**

- 徽标判定外观的来源(跟随 app 外观)
- 徽标字号与版式
