# 01: 清理扫描在高负载下停摆、取消无响应

**What to build:** 用户实报(2026-11-10):「点击清理里的扫描,再去其他 tab,回来就
卡住了,为什么?不是后台进程扫描的吗?停止扫描也没用,没有反应」。

**根因(日志取证,`~/.Pulse/logs` 当日文件):** 21:08 扫描在跑 → 到 21:15:52 用户
退出 app,其间 **7 分多钟零 Cleaner 日志**(正常 56s 扫完并打「扫描计时」)——
引擎始终没返回。同一时段主线程正常(退出按钮照常响应,terminate 栈走的是
Dashboard 按钮点击),20:59 有「系统负载 100%」告警。三件事叠在一起:

1. 扫描任务是 `.utility` 优先级,满载机器上被 OS 调度压到近乎停摆(与缓存
   装载「utility 解码被饿 21s」先例同病);
2. 协作取消只在引擎**目录入口**被消费——worker 不动,取消就没人应门,界面
   永远停在「扫描中」;
3. 取消后空闲 worker 的小睡 `try? await Task.sleep` 被取消打断后立即返回,
   退化为**满核自旋**,把还在途的 worker 挤得更慢(探针见下)。

切 tab 不是根因,只是用户离开又回来看见了停滞。

**Status:** done(2026-11-11,develop@4716bb5)

- [x] 扫描任务 `.utility` → `.userInitiated`(purge-app 同款定策:用户在等的扫描不被忙碌机器拖住)
- [x] 取消硬兜底:`cancelScan` 后 5 秒未收尾,界面强制回空态(`scanCancelForceTimeout`,init 可注入)
- [x] 扫描代数守卫:被放弃/取代的任务,晚到的进度、结果、落盘缓存一律拒收
- [x] 引擎:小睡被取消打断的空闲 worker 直接退出,不再自旋
