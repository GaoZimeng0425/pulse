# 02: 批粒度取消——巨大目录枚举在途时取消一批内必被看见

**What to build:** 用户问 purge 四条经验是否都做了(2026-11-11),第 ④ 条「取消
检查要密」确认没做:取消只在目录入口被消费,单个巨大目录(几十万条,数秒)
枚举在途时点取消要干等整目录读完。用户拍板补。顺带收口 01 票遗留项(进度代数
守卫测试)与 startScan 注释漂移。

**实现:** Live 枚举器加可选 `isCancelled` 闭包(协议形状不动,测试假枚举器零
影响),每接完一批(getattrlistbulk 一次,~几百条)查一次;true = 丢弃已读条目、
抛 `CleanEnumerateFailure.cancelled`(新档)。CleanerModel 注入
`{ Task.isCancelled }`(worker 任务上下文求值,与引擎入口检查同源)。

**写测试时推演出的真缺口(已修):** 批取消恰好发生在最后一个目录时,收尾不再
经过任何目录入口检查 → `result.cancelled == false` → **被当完整结果落盘 =
伪造**。引擎 catch 处配套:`.cancelled` 冒泡即 `markCancelledAndDrain()`
置位取消态。变异验证:去掉这两行,新测试红(「批取消冒泡必须置位取消态」);
恢复,引擎 20 例全绿。

## Comments

- **验证**:核心包批取消测试变异红→绿;缓存 roundtrip 夹具补 `.cancelled`
