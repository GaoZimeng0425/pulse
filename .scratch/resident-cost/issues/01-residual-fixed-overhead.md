# 01: 常驻成本余量归因与压降——1.11% 里未归因的 ~0.6 个百分点

**What to build:** 把 arch-review-2026-10-18/04 结项的稳态 1.11% 单核(弹窗与主窗口均关闭、5s 节奏、cputime 增量 ÷ 墙钟)**全额拆到具名项**,然后按测得的大小逐项压降、每改一项复测。/04 结项时已归因项合计只解释约 0.5 个百分点(进程采集 ~9ms/轮、菜单栏徽标 ImageRenderer 重渲 ~5ms + SwiftUI 属性图 ~6ms/轮、归组 ~4ms/轮、历史落库 ~2ms/轮),另约 0.6 个百分点没有名字。本票先给它名字,再决定砍哪里。北极星仍是 0.1%,但沿锚点④诚实口径:达到多少写多少,不设硬指标。

**Status:** ready-for-agent
**Category:** enhancement(性能)

## 为什么现在开(2026-10-20)

- 积压清零(35 张全 done),下一阶段 P2 要往采样轮里加 GPU / Neural / SMC / 声音 / 蓝牙 / 容器一批传感器;每轮固定开销不先压下去,后面每加一个传感器都要多付一份。先修地基再盖楼。
- /04 两轮(4.1% → 1.23% → 1.11%)之后把"剩余候选"明确留给了后续:菜单栏徽标改 Core Graphics 直绘替代 ImageRenderer、系统进程名判定并入归属缓存——各估 ≤0.1 个百分点、改动面大,没做。
- 今天 launchd-attribution/01 落地的新增常驻成本已实测:清单 provider 60s 一档,一次可变层 tick 在 5s `sample` 窗口里占 19 个采样点(约 15–20ms / 分钟 ≈ 0.03%),密封层冻结正常(无 "Launchd" 降级日志)。可忽略,但要并入全额账。
- **立票时未能复测稳态**:两次 60s 窗口各测得 4.05% / 4.25%,`sample` 证实当时主窗口排行页开着(`RankingCard` / `RankingListRow` / `StripChartView` / `OverviewCards` 视图体在栈上,nettop 每 5s 一趟),属"有人在看"的数字,不是稳态;**/04 的 1.11% 仍是当前基线**。本票第一项工作就是在窗口全关、落地 ≥5 分钟后按 /04 口径复测 150s。

## 方案要点与开放问题

1. **全额归因(先做,决定后面一切)**:/04 的 60s `sample` 只抓到主线程的阶段级热点。候选手段,拍板用哪几种:
   - ① 更长的 `sample`(≥150s)+ 按线程归因(工作线程上的 Sampler / SensorScheduler / 历史串行写入 / 日志刷盘);
   - ② 在 Sampler 各阶段(快照采集 / 差分 / 归组 / 下钻 / 功能模块派发 / 徽标渲染)加纯值计时累进 `SamplingStats`,诊断报告(工单 11)直接给每阶段轮均毫秒——成本极低且常驻,比一次性 profile 更有长期价值;
   - ③ 对照实验:逐个把功能模块换成 inert 源,看稳态差值。
2. **进程采集 ~9ms/轮,逐进程 sysctl 过半——但身份缓存已存在,剩余杠杆是"合并调用"不是"再缓存"**:`ProcessIdentityCache`(p1 工单 10,2026-10-16,早于 /04 测量)已把身份三元组(路径 / argv / cwd)按 exec 指纹跨轮缓存,稳态每进程 3 次调用(KERN_PROC 取 ppid / 启动时刻、PROC_PIDTASKINFO 取 CPU / 内存、rusage),校正轮 +3。注意 /04 引的 9ms 已是带缓存的数字。剩余方向:① `PROC_PIDTASKALLINFO` 一次同时拿 bsdinfo(ppid / 启动时刻 / p_comm)与 taskinfo(CPU / 内存),3 次并 2 次;② 一趟 `sysctl(KERN_PROC_ALL)` 取全表 ppid / 启动时刻,消掉逐进程 KERN_PROC。两者可叠加;字段口径与现有两条调用是否逐位等价(启动时刻精度、受限进程行为)由实施者探针拍板。
3. **菜单栏徽标 ~11ms/轮——"值不变跳过重渲"已实现,剩两条真路**:`MenuBarBadgeRenderer` 已有按(全部徽标内容 + 外观)取键的有界 LRU 缓存(容量 20),值不变时零开销;位图仍每轮重绘的原因是 CPU% 整数几乎每轮都变、缓存逐轮 miss。剩余选择:
   - A. **显示量化 / 迟滞**(如 CPU% 变化不足 2 个点不换数字):miss 骤降,且显示值不变时 SwiftUI 属性图更新(~6ms/轮)也一并省掉;**观感会变(数字刷新可能滞后一至两轮),须维护者拍板迟滞参数,不得静默上线**;
   - B. **Core Graphics 直绘文字替代 ImageRenderer**(/04 未做候选):观感零变化,把每次重绘 ~5ms 压到毫秒级以下;需逐像素对照现状,DESIGN.md 令牌不得偏移。
4. **归组 ~4ms/轮、落库 ~2ms/轮**:已经很薄;/04 的"系统进程名判定并入归属缓存"估 ≤0.1,按归因结果决定做不做。
5. **"有人在看"时的成本(顺带观察,不承诺本票修)**:`AppIconCache`(NSCache,按 bundle 路径)**已存在**——本次 5s `sample` 里 `AppIconCache.icon(forBundle:)` 与 `RankingListRow.icon.getter` 各 50+ 采样点并伴随 `NSWorkspace icon` / `NSImage` / FSNode 读文件,热点在缓存存在的前提下仍在,要先查清是**逐轮 miss**(键不稳 / NSCache 回收)还是**命中后的 NSImage 表示逐次解码 / 栅格化**。这是观看态成本,与本票的常驻口径不同,留 triage 决定并入还是另立票。另一个实测数据点:主窗口排行页开了一夜,cputime÷墙钟 全程均值 **3.77%**——观看态是稳态(约 1.1%)的三倍半。

**Key interfaces:**
- `SamplingStats`(纯值账本)与 `DiagnosticReport`(诊断报告取数):新字段与展示。
