# 02: MCP server——独立 stdio 可执行,官方 swift-sdk,读 WAL 历史库作答

**What to build:** `pulse-mcp` 独立 stdio 可执行(官方 modelcontextprotocol/swift-sdk,
零权限零单向门,探针③绿灯的直接消费)。读 `~/Library/Application Support/Pulse/
history.sqlite`(WAL 只读连接,app 写者并存安全——探针实测)回答 AI 客户端提问;
app 不在跑也能答(回退最近落库样本)。首批工具三个:

- `why_cpu_high`:现在谁在吃 CPU——最近 sample_min top 进程组 + groups 名称 +
  system_min 系统趋势,交叉成一段结构化答案(弹药:sample_min 666k 行/298 组);
- `current_metrics`:当前读数(CPU/RAM/磁盘/网络/温度/GPU/功率,取各 metric
  最近值,gauge_min 窄表 + system_min);
- `history_query`:按 metric + 时间窗查历史(gauge_min/gauge_hour 按过滤)。

工程形状:新可执行 target(纯 Foundation + GRDB + swift-sdk,不碰 AppKit,
查询逻辑进 PulseCore 复用既有 Queries 层);产物嵌 Pulse.app bundle,
README 给 AI 客户端配置指引(claude desktop / ZCode 等)。

## Agent Brief

> *This was generated by AI during triage.*

**Category:** enhancement
**Summary:** 独立 stdio MCP server(官方 swift-sdk)读 Pulse WAL 历史库,首批三工具,
app 不在跑也能答。

**Current behavior:**
历史库(WAL 模式 sqlite,`~/Library/Application Support/Pulse/history.sqlite`)
只有 app 写者使用;AI 客户端(Claude Desktop / ZCode 等)无法查询 Pulse 数据。
sample_min 每分钟每进程组样本、gauge_min 窄表趋势量、system_min 系统级均已
落库(探针实测 66 万行样本在库),查询层已在 PulseCore。

**Desired behavior:**
新可执行 target(产物名 `pulse-mcp`;纯 Foundation + GRDB + 官方 swift-sdk,
不 import AppKit/SwiftUI;查询逻辑复用 PulseCore 只读查询,缺的补进包里带单测;
产物嵌 Pulse.app bundle,README 补 AI 客户端配置样例)。stdio JSON-RPC(MCP
协议),三个工具:
- `why_cpu_high`:最近采样窗 top-N 进程组(默认 5,参数可调)——组名、项目
  归属(有 project_root 的)、CPU 均值/峰值,附系统级趋势,合成结构化答案;
- `current_metrics`:各 metric 最近值(CPU/RAM/磁盘/网络/温度/GPU/功率),
  每项带数据年龄;
- `history_query`:metric 枚举 + 时间窗 → 降采样序列(gauge_min/gauge_hour)。
只读连接打开历史库(WAL 跨进程读者安全,探针实证);库不存在/为空时诚实报
"无数据",不崩不编造。

**Key interfaces:**
- PulseCore 查询层:只读 API 从既有 Queries 取用;新查询进 PulseCore 带单测
- swift-sdk 的 Server/Tool 注册:三工具输入 schema 与 JSON 输出结构
- project.yml:新 target + 依赖声明(xcodegen 生成,不手改工程文件)
