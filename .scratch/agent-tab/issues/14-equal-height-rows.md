# 14: 同行等高改用可靠排法,弹窗数字卡两列两行

**What to build:** 用户 2026-11-25 实报弹窗智能体页「一排的卡片高度必须一致,而且这里
也不应该是 4 个一排」。查实两层:

1. 「同行等高」靠 `.frame(maxHeight: .infinity)` 撑框,但底色画在框里面——框撑开了,
   肉眼看到的卡也不变高。主窗口数字卡排看着齐,是四张卡行数碰巧相同。
2. 弹窗原生列表按「宽定、高无上限」给整页量高,弹性框把消耗子页量成
   `greatestFiniteMagnitude`:「消耗总览」吃掉整个滚动区(截图里汇总卡下方那片就是
   它的底色),日历图 / 走势 / 项目卡落在离顶数百万点处,永远滚不到。

探针(离屏、不上屏):同骨架替身,现状写法量出 1.797e308、汇总卡高约 500 万点;
换成「行高明确提给每一张」的排法后量出 997 点、四张卡依次排开。

**改动:**

- 新 `EqualHeightRow`(CardFamily):列等宽,行高 = 行内最高一张的自然高,再把
  (列宽, 行高) 明确提给每一张;`sizeThatFits` 不理会宿主的高度提案。卡自己的弹性框
  要在底色里面(先撑框、后铺底色)。
- 数字卡排:主窗口四张一排;弹窗两列两行(用户拍板)。撤掉不生效的
  `minimumScaleFactor(0.5)`(挂在容器上,管不到里面的 Text)。
- 项目卡网格逐行改走 `EqualHeightRow`,项目卡先撑框后铺底色。

**验收:** 点菜单栏图标 → 智能体:汇总卡正常高度、四张小卡两行齐平、数字完整;往下滚
能滚到日历图 / 走势 / 项目卡。主窗口智能体页外观不变。

**Status:** done(2026-11-25,fix/agent-equal-height;装机目验归用户)

## Out of scope

- 总览 / 清理总览的 `AdaptiveCardGrid` 与两卡并排 `AdaptiveCardPair` 是同一种
  「框在外、底色在内」写法:只在主窗口出现,不受量高撑爆影响,同排卡目前自然高相同;
  换排法另票。
- 消耗子页在弹窗里卡间距仍是 16(规范是 8),留给消耗页重构一起做。
- 主窗口消耗页重构(项目卡太密 / 没有主次 / 零碎重复 / 配色)另起议题。
