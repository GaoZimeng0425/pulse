# P2 spec:系统传感器六家族(GPU / ANE·五路功率 / SMC 温度风扇 / 声音 / 蓝牙 / 容器)

Status: ready-for-agent
来源:2026-10-22 kickoff(同目录 `kickoff.md`,含本机探针实证)+ 三轮 grill 拍板(kickoff §6)。
词汇:本 spec 用词以根目录 `GLOSSARY.md` 为准(五路功率/派生传感器/传感器命名表/趋势量 为本轮新增词条)。

## Problem Statement

P1 之后,Pulse 已经能回答"什么在占用 CPU/内存/磁盘/网络",但复刻目标(Vitals 全量面板)里的六个家族还缺失:GPU 在干什么、ANE(神经网络引擎)的功率、机身温度与风扇、声音输出、蓝牙外设电量、Docker/OrbStack 容器状态——全都看不到。用户跑 AI 工作流(agent 编译风暴、本地模型)时,GPU/ANE 功率飙升本应是"模型在干活"的最直接信号,现在却是观测盲区。

## Solution

六家族传感器全部以免 root 路径接入,沿用既定架构插槽:每家族 = 核心包纯值模型 + Live 适配器 + 功能模块挂 MonitorFeatures 注册表 + 按各自节奏登记 SensorScheduler,窗口内容一律过可见性门控。主窗口新开四页(GPU / 传感器 / 外设 / 容器),弹窗同步加五个紧凑组;温度派生值、GPU 利用率、五路功率进 30 天历史;菜单栏徽章维持四槽不动。开机常驻成本增量按"低频 + 门控"纪律控制在可忽略量级,收口票复测稳态口径。

## User Stories

1. 作为 Pulse 用户,我想要主窗口 GPU 页显示 GPU 总利用率大数、Renderer/Tiler 细分与显存占用,以便知道图形负载来自渲染还是贴图管线。
2. 作为 Pulse 用户,我想要 GPU 利用率带趋势线,以便判断 GPU 高占用是瞬时尖峰还是持续状态。
3. 作为 AI 工作流用户,我想要 ANE(神经网络引擎)的瞬时功率与按芯片上限的归一化百分比,以便看到本地模型推理何时真正在用 NPU。
4. 作为 AI 工作流用户,我想要整机功耗视图(五路功率:CPU/GPU/ANE/RAM/SoC 各自的瓦数与占比),以便一眼看出"这波负载烧在哪个芯片上"——这是 Vitals 都没做深的部分。
5. 作为 Pulse 用户,我想要五路功率的差分首读显示占位而不是巨刺或假 0,唤醒后第一轮被丢弃(首读与唤醒首轮都不出读数,不入历史与走势——p2-review/01 拍板,2026-10-24),以便睡眠回来后图表不出现假尖峰或假低谷。
6. 作为笔记本用户,我想要传感器页显示温度派生值(Average/Hottest CPU/GPU/SoC)置顶、逐传感器明细折叠其后,以便日常看一眼均值,排查时再展开全表。
7. 作为笔记本用户,我想要风扇转速(当前/最小/最大)以进度条展示,以便风扇起飞时知道是哪一队在转、转到了几成。
8. 作为长期使用者,我想要温度派生值、GPU 利用率、五路功率进 30 天历史库,以便回看"这台机器这周的散热/负载趋势"。
9. 作为 Pulse 用户,我想要传感器命名表外的未知键归"未知"组默认折叠而不是被丢弃,以便换新机器时新键不导致卡片空白。
10. 作为外设用户,我想要外设页列出蓝牙设备的连接态、电量与信号强度,以便妙控板/耳机没电之前先看到。
11. 作为外设用户,我想要 Apple 外设、蓝牙缓存、GATT 三源电量按统一规则合并成一张设备表(歧义即弃),以便不同品牌的设备都有一行可信电量。
12. 作为外设用户,我想要蓝牙扫描只在设备页/弹窗组可见时进行,睡眠时停扫、唤醒后重启,以便蓝牙电量这种慢变量不为常驻成本买单。
13. 作为 Pulse 用户,我想要外设页的声音区显示默认输出设备、系统音量与静音状态,以便不用开系统设置就能确认"声音去哪了"(声音为非重点家族,只做展示层)。
14. 作为 OrbStack 用户,我想要容器页列出容器名称、运行状态、CPU 与内存占用,以便本地服务是否在跑一眼可见。
15. 作为 OrbStack 用户,我想要 OrbStack 未运行/无 docker.sock 时容器页显示安静空态,以便产品不报错、不轮询重试风暴。
16. 作为菜单栏用户,我想要弹窗里出现 GPU/温度/蓝牙/声音/容器五个紧凑组,以便不打开主窗口也能瞥一眼六家族的核心读数。
17. 作为菜单栏用户,我想要弹窗温度组只放派生值(Average/Hottest/最快风扇),以便弹窗不因逐核温度表变得不可用的高。
18. 作为菜单栏用户,我想要徽章维持现状(CPU/RAM/磁盘+网络四槽),以便迟滞与直绘的既有调优不被翻搅。
19. 作为隐私敏感用户,我想要全部采集走免 root 的用户态 API,无网络请求、无子进程(蓝牙兜底源 v1 不做),以便公司机友好不变。
20. 作为系统监视器用户,我想要读不到的传感器显示空白卡/上次好值而不是崩溃或伪造,以便半私有 API 在 macOS 大版本后退化时产品活着。
21. 作为系统监视器用户,我想要 SMC 坏值防御(<10 或 >120 沿用旧值、0 或 >110 丢弃),以便 UI 永远不出现 -1°C 或 200°C。
22. 作为电池页用户,我想要电池功率优先读 SMC(读不到回退电流×电压),以便功率数字更准。
23. 作为主窗口用户,我想要 11 个 tab 在加宽后的窗口里全部平铺可见,以便任何家族一键直达。
24. 作为成本敏感用户,我想要六家族全部按节奏矩阵运行(可见 5s / 历史档 30s / 状态族可见 30s 不可见停 / 声音纯事件),以便稳态常驻成本不因六家族显著上涨。
25. 作为成本敏感用户,我想要收口票按既有指纹协议(关两窗 15s 采样栈全零)复测,以便确认新传感没有制造新的隐形观看态。
26. 作为历史页用户,我想要新趋势量的历史复用既有分钟/小时 rollup 管线与 sparkline 展示,以便三家族趋势与 CPU/内存趋势同一种看法。
27. 作为系统监视器用户,我想要声音卡事件驱动(设备/音量变化通知),以便零轮询也能即时反映插拔耳机和改音量。

## Implementation Decisions

**架构插槽(ADR-0003/0004/0006,全部沿用)**:每家族 = 核心包纯值模型 + app Live 适配器 + @Observable 功能模块薄壳挂 MonitorFeatures 注册表;非心跳型一律登记 SensorScheduler 按节奏驱动;新页面/新卡消费逐轮数据必须过可见性门控(MonitorVisibility 信号体系),弹窗与主窗口关树后不得逐轮重算(验收 = 既有指纹协议)。

**测试缝(已与用户确认)**:唯一采集缝 = SensorProvider 边界上的原始载荷——Live 适配器只做 OS 调用交回原始数据结构(IORegistry 字典 / IOReport 通道样本 / SMC 键值字节 / CoreAudio 属性 / 蓝牙三源元组 / docker HTTP JSON),解析、解码、单位换算、差分、合并全部在核心包纯值模型,以合成载荷单测。不新增缝的种类。

**GPU 家族**:读 IORegistry 加速器服务的 PerformanceStatistics:总利用率、Renderer/Tiler 细分、显存分配/在用。防御:>100 钳 100;电源管理关电(AGCInfo)时利用率归 0 视为正常态;缺字典跳过该设备;型号/核心数等静态信息进程级缓存一次。温度刻意不进 GPU 家族(本机 M4 字典无温度键),归 SMC。节奏:可见 5s / 不可见 30s(历史档)。

**ANE·五路功率家族**:同一 IOReport "Energy Model" 订阅一次采样,同时产出 ANE 卡与五路功率视图(CPU/GPU/ANE/RAM/SoC)。关键实现事实(2026-10-22 探针实证):该 API 在 macOS 26 返回**响应字典**(含通道数组键),不是 stats 时代的裸数组——Live 解包按新形状写;通道单位逐通道不同(mJ/nJ 等),必须按单位标签换算成焦耳再差分;功率 = 能量差 ÷ 实测时差(不用标称间隔,档位切换不断账);差分首读与系统唤醒后首轮只记基线、不出读数(原「首读返回 0」,p2-review/01 改);通道按名过滤(ANE/GPU/CPU/DRAM 等前缀)。ANE 归一化用芯片最大功耗表(含 M4 行,随 stats MIT 注明)。节奏:与 GPU 同档同门控。

**SMC 温度/风扇家族**:移植 stats 的 SMC 客户端(MIT,文件头注明来源)——AppleSMC 用户态连接,sp78/fpe2 等按 dataType 解码。传感器发现 = 全键枚举 × 内置传感器命名表 × 每核通配展开;表外键进"未知"组默认折叠。派生传感器(Average/Hottest CPU/GPU/SoC、最快风扇)由基础读数计算,UI 置顶。风扇:数量/当前转速/上下限。坏值防御:M2 坏传感器先例照抄(温度 <10 或 >120 沿用旧值,0 或 >110 丢弃)。顺手活:电池功率优先读 SMC 键,读不到回退电流×电压(研究档案 §2.3 的 ARM 更优路径)。发现结果进程级缓存。节奏:可见 5s / 不可见 30s(历史档)。

**声音家族(非重点,展示层)**:CoreAudio 默认输出设备 + 音量/静音的**纯展示**(不做控制交互)。纯事件驱动(设备/属性变更通知),零轮询。每 App 音量层不进 v1(2026-10-22 spec 阶段用户修订:声音控制不是重点);若未来做,参考 BackgroundMusic 的点子(GPLv2+,只取点子不碰代码:它的每 App 音量靠虚拟声卡驱动劫持默认输出,与监视器定位不符;读侧公开进程 tap API 是更合适的探矿方向)。

**蓝牙家族**:三源合并——① IORegistry 的 Apple HID 事件服务(Apple 外设)② 蓝牙偏好缓存(免权限;缓存电量 1 当 100 解释)③ CoreBluetooth GATT 电池服务(按需连接)。已配对/连接态与 RSSI 来自 IOBluetooth 设备列表(RSSI 127=未知)。合并规则:地址规整(统一分隔与小写)→ 唯一名称 → 厂商/产品 ID 三级匹配,歧义即弃。system_profiler / pmset 子进程兜底源 v1 不做。睡眠停扫/唤醒重启;GATT 只在需要读某设备时建连。节奏:可见 30s / 不可见完全停。

**容器家族**:docker.sock 上的 HTTP API(本机 = OrbStack,标准 sock 路径已实证)。容器列表 + 每容器单发 stats 快照(非流式,连接常开已否决);socket 缺席 = 安静空态,不重试风暴。节奏:页可见 30s / 不可见完全停。

**历史落库**:只进趋势量(温度派生值/GPU 利用率/五路功率),复用既有分钟/小时 rollup 与留存管线;状态量(蓝牙电量/音量/容器状态)刻意不进。历史档 = 不可见 30s 低频采样。

**主窗口 IA**:新开四页 → 共 11 tab:GPU(利用率/显存/ANE/五路功率区)、传感器(温度/风扇)、外设(蓝牙/声音)、容器。主窗口最小宽度上调或 pill 微收窄,随 GPU 票一次落地;新数值先补 DESIGN.md 令牌表再写视图。

**弹窗**:五个新组全进(全组展示原则延续),组内紧凑形态:GPU 组=利用率一行;温度组=派生值;蓝牙组=设备电量行;声音组=设备+音量;容器组=运行中列表。

**徽章**:不动。四槽、迟滞参数、直绘缓存全部维持。

**节奏矩阵(定稿)**:GPU/五路功率/温度风扇 = 可见 5s、不可见 30s(历史档);声音 = 事件驱动;蓝牙/容器 = 可见 30s、不可见停。所有差分型指标唤醒后清基线/丢首轮。

**票据形状**:八票,探针票先行(SMC 真读数键表 dump、GATT 电池读、docker.sock HTTP 一发;原 CoreAudio tap demo 项随声音降级裁撤),收口票保历史接线 + 稳态复测 + 指纹验收。

## Testing Decisions

- **好测试的标准**:只测外部行为(载荷进 → 读数/派生值出),不测实现细节;合成载荷覆盖防御分支(坏值/缺键/单位混合/歧义匹配),不起宿主、不占真机负载(既有测试纪律)。
- **核心包(主要战场)**:六家族的解析/解码/换算/差分/合并/派生模型,全部 `swift test` 合成载荷单测;先例 = 既有解析与差分模型的测试形状。必测不变式:单位换算数量级(mJ/nJ 相差 10⁶ 不许错)、差分首读与唤醒首轮不出读数、SMC 坏值钳位、蓝牙歧义即弃、docker JSON 容错。
- **调度与门控**:SensorScheduler 注入 sleep 的既有形状,覆盖节奏档、事件流终态日志。
- **Live 薄壳**:PulseTests 起宿主,每家族"真读一次不崩 + 结构健全"冒烟(先例 = 既有 Live 适配器测试);SMC/GATT/tap 的真机验证随各自探针票。
- **UI**:不单测;DESIGN.md 令牌门禁 + 用户目验。
- **收口验收**:关两窗 15s 指纹全零(ADR-0006 协议)+ 稳态成本 150s 窗复测,记入收口票。

## Out of Scope

- P3 全部:root helper、MCP server、每 App 网络归因、Agents 用量卡。
- 声音每 App 音量层整体(2026-10-22 用户修订:声音控制不是重点;含输入电平/麦克风权限,一并出 v1)。
- 蓝牙 system_profiler / pmset 子进程兜底源。
- docker stats 流式常开连接。
- 徽章面任何改动。
- 容器数据卷占用行、可回收产物扫描(未拍板,挂后续)。
- GPU 帧率(DCP 计数差分,研究档案标注的免费思路但 Vitals 面板没有)。
- 隐藏 HID 传感器通道(私有度高,留探针)。
