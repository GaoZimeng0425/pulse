**Summary:** 历史仪表管线收敛——传感器模型自报 `historyGauges`,存储换窄表 `(ts, key, avg, max)`,加一个趋势量从此只动两处(GaugeKey 定义 + 模型自报一行),不再写 schema 迁移。

**Current behavior:**
仪表型样本(GPU 利用率 / SMC 温度均值与最热 / 五路功率)由各 feature 广播 per-family 的
`FeatureEvent` case(`gpuSample`/`smcSample`/`powerSample`),`HistoryFeed` 按家族暂存、
`HistoryEngine.ingest` 带逐量参数、rollup 缓冲逐量字段、落库到宽表 `system_min`/`system_hour`
的逐量 REAL 列(p2-sensors-v2 加的 8 列);查询层逐量 SQL。加一个量要改 7 文件 ~11 处。
SMC「全机最热 / 均值」的折算住在 `HistoryFeed.recordSmc` 而非 SMC 模型。

**Desired behavior:**
- 核心包定义 `GaugeKey`(String rawValue 枚举,rawValue 即存储键;既有 8 个量各一 case,
  五路功率平铺不嵌套)。传感器读数模型自报 `historyGauges: [GaugeKey: Double]`
  (SMC 的均值/最热折算随之搬进 SMC 模型,消除 Feed 里的口径外置)。
- `FeatureEvent` 的三个 per-family 样本 case 收成一个 `.gauges([GaugeKey: Double])`
  (或等价的单一携带形状);`HistoryFeed` 按 key 暂存,`HistoryEngine.ingest` 参数收敛为
  gauges 字典;rollup 缓冲与小时聚合按 key 分桶(avg 取均、max 取最大)。
- 新窄表 `gauge_min(ts, key, avg, max)` 与 `gauge_hour(ts, key, avg, max)`,
  索引 `(key, ts)`;宽表 8 个仪表列删除。迁移名接在 p2-sensors-v2 之后;迁移事务内:
  先把宽列变换进窄表(每有值列一行),再 DROP 旧列。**迁移执行前由 `HistoryDatabase`
  打开路径备份库文件**(同目录 `history.sqlite.bak-<yyyy-MM-dd>`,已存在则跳过备份直跑迁移)。
- 查询层:`HistoryQueries` 的温度/功率/分项查询改读窄表;07 票的分项药丸语义不变
  (按 key 查即分项)。历史页 UI 零变化。
- 差分/聚合语义保持:缺席量不伪造 0(NULL 语义延续);分钟→小时聚合与现状口径逐位一致
  (以 SensorHistoryWiringTests 既有断言为基准迁移)。
