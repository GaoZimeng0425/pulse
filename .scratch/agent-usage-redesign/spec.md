# 智能体「消耗」页重构 · 规格

**Status:** ready-for-agent(2026-11-26;测试缝与拆票经用户确认)
**原型(定稿方向的来源):** `prototype-usage-page.html`,`?mode=c`
**拆票:** `issues/01`–`issues/04`

## Problem Statement

用户打开主窗口的智能体「消耗」页,觉得丑,具体是四件事:

1. **项目卡太密**:每个项目一张约 250pt 高的大卡,五格读数、两条构成条、一排图例、
   一行元信息全摊开;十个项目叠起来三千多点,看不出先看哪。
2. **没有主次**:四张卡(消耗总览 / 日历 / 走势 / 项目)一样大、一样重,上下排;
   卡头全是同一种青色小标题,满屏 10.5pt 灰字。
3. **零碎重复**:「7 天 | 30 天」在走势卡头和项目卡头各出现一次;总览卡里再套
   四张小卡;「重新扫描」是个不起眼的文字按钮。
4. **配色不好看**:满屏一种青;项目、来源、模型之间没有区分色;青色本身也不想要。

另外有一个顺带的口径问题:今日环比拿没过完的今天比完整的昨天,白天几乎永远
是负的(用户实拍 19:11 显示 ▼ -53%),像个全天不灭的警报。

## Solution

整页改成三段,**主卡 → 日历 → 项目榜单**,弹窗是同一套卡片的紧凑档:

- **主卡**:左边是今日消耗的大数字、按进度折算后的今日环比、三格小读数
  (N 天合计与较上期 / 日均与峰值 / Claude 用量);右边是近 N 天按来源分两层的
  面积走势。卡头右侧是全页唯一的「7 天 | 30 天」开关(标准药丸页签条),
  同时管走势、小读数和项目榜单。原来的数字卡排和独立走势卡并入主卡后撤除。
- **日历**:一年热力墙不变;卡头右侧「重新扫描」换成 Liquid Glass 按钮,
  「天 | 周」不变;标题改「日历」。
- **项目榜单**:每个项目一行(名称、在跑标记、来源分段条、占比、消耗、环比),
  点一行原地展开明细(五格读数、模型构成、来源构成、元信息);默认前 10 个,
  末行展开 / 收起。项目大卡撤除。
- **配色**:页面主色换成青柠,tab 图标同色;Claude 与 ZCode 两个来源各一色,
  模型三档柔和异色;主色只用在选中态、今日数字、日历色阶这些关键处。

## User Stories

**主卡**

1. 作为用户,我想一进消耗页就看到今天用了多少 token,所以把它放在页面最上面、
   字最大。
2. 作为用户,我想知道今天比昨天是快是慢;今天还没过完,所以环比要按已过时间
   折算后再比,而不是半天比整天。
3. 作为用户,我想知道折算后的环比是怎么算的,鼠标停上去有说明。
4. 作为用户,大数字永远显示真实用量,不要被折算放大。
5. 作为用户,我想看到近 7 天或 30 天的合计、日均、峰值。
6. 作为用户,我想知道这一段的合计比上一段多了还是少了。
7. 作为用户,我想一直看得到 Claude 的 5 小时窗用量、本周用量和窗口重置时间。
8. 作为用户,我想只切一次「7 天 | 30 天」,走势、小读数、项目榜单一起变。
9. 作为用户,我想一眼看出走势里哪一层是 Claude、哪一层是 ZCode。
10. 作为用户,我想把鼠标停在走势上看到那一天的日期、总量、两家各多少和四桶明细。
11. 作为用户,今天还没过完,我想让走势里今天的点画实际值,悬停时标明是今天。
12. 作为用户,切范围的时候我不想看到上一个范围的悬停残留。
13. 作为用户,账本还没有数据时,我想看到明确的空态和「重新扫描」的出路。
14. 作为用户,读不到 Claude 用量快照时,我想看到「—」,不要假数字。

**日历**

15. 作为用户,我想看一年的每日用量热力墙,并能切成按周看。
16. 作为用户,我想用一个一眼能找到的按钮触发全量重新扫描。
17. 作为用户,扫描进行中我想看到它在转,而且点不动(不能重复触发)。
18. 作为用户,我想知道最多一天 / 最多一周是多少。

**项目榜单**

19. 作为用户,我想一行看完一个项目:叫什么、有没有在跑的会话、占多少、用了多少、
    比上一段多了还是少了。
20. 作为用户,我想项目按消耗从高到低排,一眼看出谁最费。
21. 作为用户,我想从占比条看出这个项目的用量主要来自哪家来源。
22. 作为用户,我想点一行就展开这个项目的五格读数(Input / Output / Cache R /
    Cache W / Cache×)、模型构成、来源构成和元信息;再点收起。
23. 作为用户,我想同时展开好几个项目做对比。
24. 作为用户,切 7 / 30 的时候我想让展开状态保持。
25. 作为用户,项目超过 10 个时我想先看前 10 个,再一键展开全部 / 收起。
26. 作为用户,窗口内没有项目数据时,我想在卡里看到空态,而不是一张空卡。
27. 作为用户,我想重进子页时一切回到默认(7 天、全部收起)。

**配色**

28. 作为用户,我想让智能体页有自己的主色,在 tab 条上和别的页区分得开。
29. 作为用户,我想主色只出现在关键处,不要满屏都是。
30. 作为用户,我想 Claude 和 ZCode 在走势、占比条、图例里永远是同一种颜色。
31. 作为用户,我想不同模型用不同但柔和的颜色区分。
32. 作为用户,我想深色和浅色外观下这些颜色都看得清。

**弹窗与其它**

33. 作为用户,我想在菜单栏弹窗里看到同一套卡片(紧凑档),信息不缺。
34. 作为用户,我想弹窗里卡片之间的间距和别的页一致(8)。
35. 作为用户,我想在弹窗里也能切范围、点开项目明细。
36. 作为用户,我想弹窗滚动顺畅,卡片不再被量成异常高度。
37. 作为读屏用户,我不想让图表被朗读,数值由旁边的文字承载。

## Implementation Decisions

**页面结构**

- 消耗子页 = 主卡 → 日历 → 项目榜单。账本为空时整页仍是一张空态卡(不变)。
- 数字卡排(今日 / N 天合计 / 日均 / Claude 用量 四张小卡)与独立走势卡撤除,
  内容并入主卡。项目大卡与它的网格撤除,换成榜单。
- 「会话」子页不动,但它的强调色跟着 tab 主色一起变(同一个取色口)。

**范围状态**

- 范围(7 / 30 天)在子页里只有一个状态,同时驱动:主卡走势、主卡三格小读数、
  项目榜单(标题带「近 N 天」,排序 / 占比 / 环比都按这个窗口算)。
- 今日大数字和今日环比不随范围变。日历的「天 / 周」独立于范围。
- 重进子页回默认:7 天、项目全部收起。日历粒度沿用现状。

**主卡版式**

- 沿用 DESIGN.md「指标卡两形态」里的大卡:左列 200pt(11pt 说明、大数字
  figure-main、读数)+ 右侧撑满的走势,内距 16;正文高 184——读数格带副行,
  标准的 176 放不下(实测自然高 183),用户 2026-11-26 拍板比标准高 8pt、
  不收紧间距。紧凑档竖排、内距 12、走势 64。
- 今日环比与「今日消耗」同一行(靠右):不与大数字同行(44pt 的读数加环比,
  200pt 放不下),也不单占大数字下面一行(左列要再高 21pt)。用户四选一定了这个。
- 大卡新增一行**卡头**(卡头标题 + 右侧配件槽),配件槽里放作用于整卡的范围
  开关。这一条补进 DESIGN.md 第 4 条组件规范。
- 左列三格读数:`N 天合计`(副行:较上期环比)/ `日均(N 天)`(副行:峰值)/
  `Claude 用量`(通栏,副行:本周 · 重置)。读数是统计值(12 semibold),不是
  大数字;标签 10.5 secondary。
- 卡头、范围开关、今日大数字与环比之间的具体摆法写在页面规格注释里
  (ADR-0011),不进 DESIGN.md。

**全天等效量与今日环比**

- 「全天等效量」= 进行中的今天的用量按已过时间折算成的等效全天用量:
  今日用量 × 86400 ÷ max(已过秒数, 6 小时)。6 小时下限是日历色阶的现行规则,
  这次抽成一个两处共用的函数,不许各写一份。
- 今日环比 =(今日全天等效量 − 昨日用量)÷ 昨日用量;昨日为 0 → 无基准,显示「—」。
- 全天等效量只用于比较(日历色阶、今日环比),任何读数都不显示它。
- 时钟可注入(沿用现有 `calendar` / `now` 参数),测试不依赖真实时间。

**按来源分层的走势**

- 每日合计在现有每日结构上补两个来源分量(Claude / ZCode),由账本行按来源
  分别累加;缺天补 0;四桶分项仍按合计给。
- 走势是两层面积加两条线(ZCode 在下、Claude 在上),工具库仍用系统图表库;
  悬停浮层沿用现有「图表悬停读数与浮层」:日期(今天标「今天」)+ 总数,下面是
  两列明细格——先两家,再四桶(有分项时才有)。这一条补进 DESIGN.md 第 14 条。
- 坐标轴、标签抽稀、竖线贴数据点等沿用现有走势的做法;切范围清悬停。

**项目榜单**

- 建在 DESIGN.md「排行列表」标准件之上:卡内标题、表头(项目 | 占比 | 消耗 | 环比)、
  行尺寸走 `RowMetrics` 两档、行尾留展开箭头一列、悬停底色、截断末行、卡内空态。
- 行 = 行首文件夹图标 + 名称 + 「在跑 N」芯片 + 来源分段条(定宽取 meter 条宽,
  长度按窗口内最大项目归一,两段 = Claude / ZCode)+ 占比 + 消耗 + 环比 + 箭头。
  紧凑档(弹窗)是两行:上行名称 + 消耗,下行小字「在跑 / 占比 / 环比」——一行五列
  实测名称只剩约 61pt、带芯片的名字被挤成「…」,用户 2026-11-26 拍板改两行。
- 图标色:今天活跃或在跑时取该项目的主来源色(Claude 占比过半取 Claude 色,
  否则 ZCode 色),否则取「停 / 未连接」的灰。
- 点行原地展开明细块(卡内抬升底、内层圆角):五格读数 → 模型构成 → 来源构成 →
  元信息(活跃天数、会话数、请求数、今天活跃 / 静了 N 天)。主窗口与弹窗都原地展开。
- 默认前 10 个(`{layout.agent-project-limit}`),末行展开 / 收起沿用现有文案与交互。
- 排序、占比、环比、在跑数、五桶、模型与来源份额全部来自现有的项目窗口派生,
  不新增口径。

**颜色**

- 智能体页有了自己的页面强调色 `{colors.accent-agents}`,不再借用蓝牙青。
  两个 tab 条(图标条、药丸条)统一从一个取色口取色:页强调色优先(智能体、清理),
  其余取指标色;不再各自特判。
- 来源色 `{colors.agent-source-claude}` / `{colors.agent-source-zcode}` 各自独立
  成令牌;模型色三档 `{colors.agent-model-first / second / third}` 取代原来
  「借用指标色」的三档。取值以原型 `?mode=c` 为准(浅 / 深):
  强调色 `#5a921a / #a6d94a`;Claude `#c9622f / #e8946a`;ZCode `#6a4fe0 / #8f7cf5`;
  模型一 `#1a78bd / #58a8e8`;模型二 `#bd3a7c / #e070a8`;模型三 `#93730f / #cfab4a`。
- 涨跌的正负色不变。

**Liquid Glass 按钮**

- 「重新扫描」用系统玻璃按钮样式(系统 Liquid Glass 按钮,不自绘底、不加描边),
  标签 = 符号 + 文字;扫描中换成转圈 + 「扫描中」并禁用。这是新的通用界面件,
  在 DESIGN.md §Components 立规范(卡头上的主动作)。其它页的「卡头文字按钮」不变。

**令牌表的增删(DESIGN.md)**

- 增:上列六个颜色令牌。
- 删:`{typography.figure-stat}`(数字卡排撤了,无使用者)、
  `{layout.agent-chart-two-column-min-width}`(两图并排的断点不再存在)。
- `{layout.agent-project-limit}` 保留,语义改为榜单默认展示上限。

**术语表**

- 新增「来源 (Source)」与「全天等效量 (Day-equivalent)」两条(智能体账本一节)。

**不动的**

- 账本表、采集、扫描、MCP 查询工具一律不动。清理页「AI 模型」品类的颜色不动。

## Testing Decisions

好的测试只测外部行为(载荷进 → 读数出),合成夹具,不起界面,不占真机负载。
视图的长相靠预览和用户装机目验(仓库现行约定)。自动化只落在三处(用户已确认):

1. **账本的派生计算**(核心包 XCTest,时钟注入):
   - 今日环比按全天等效量算:半天过完等于昨天全天 → 正数;不足 6 小时按 6 小时
     下限;昨日为 0 → 无基准。
   - 日历色阶与今日环比共用同一个折算规则(抽函数后原色阶用例照旧全绿)。
   - 每日合计的来源分量:两家分开累加、缺天补 0、合计等于两家之和。
   - 项目排序、占比、环比继续由现有窗口派生用例钉住。
   先例:`AgentUsageWindowTests`、`AgentHeatScaleTests`(夹具日期从 now 推导)。
2. **颜色登记**(app 侧 XCTest):
   - 新强调色、来源色、模型色钉死浅深数值;浅深互异。
   - 新强调色与全部指标色、清理页强调色互不相等。
   - tab 取色:智能体 tab = 智能体页强调色,清理 tab = 清理页强调色,其余 = 指标色。
   先例:`MetricAccentTests`、`MetricTabModelTests`。
3. **弹窗量高**(app 侧 XCTest):真实的消耗子页按弹窗量法量出的高度有限(沿用
   现有的量高用例,它钉住了子页的入参形状)。
   先例:`EqualHeightRowTests`。

## Out of Scope

- 「会话」子页的重排(只跟随主色)。
- 日历按来源分色;日历新增别的档位。
- 项目榜单的点列排序、单项目下钻页。
- 「和昨天同一时刻比」的精确口径(需要日内数据,账本是天粒度)。
- 窗口合计、日均、项目环比里「今天没过完」的小偏差(今天只占窗口的 1/7 到 1/30,
  维持现状)。
- 清理页「AI 模型」品类的颜色(仍借用蓝牙青)。
- 总览页 / 清理总览卡片网格的旧等高写法(agent-tab/14 已记为遗留)。
- 美元成本、精确最后活跃时刻(`.out-of-scope/agent-cost-and-last-active.md`)。

## Further Notes

- **前序修复**:弹窗里消耗页曾被量成天文高度、后面的卡永远滚不到,已在
  agent-tab/14 修掉(新排法 `EqualHeightRow` + 回归测试)。新页面沿用该排法,
  量高用例继续钉着。
- **主色的来路**:现有指标色占了大半个色环,空出来的基本只有紫和黄绿;
  三套候选原型里用户选了青柠。
- **历史拍板的更正**:今日环比的折算规则最初口述成「不足 6 小时不折算」,
  查代码后确认日历色阶的现行规则是「不足 6 小时按 6 小时算」,已向用户更正,
  以本规格为准。
- **不立 ADR**:换主色、改结构都容易回头,决策经过记在票里。
