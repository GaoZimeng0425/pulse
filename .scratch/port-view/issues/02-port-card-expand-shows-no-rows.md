# 02: 端口卡「显示全部」展开后不多出行

**What to build:** 服务页监听端口卡里,端口超过 20 个时末行显示「显示全部(另 N 个
端口)」。点它应该把其余端口也列出来;现在点了只换成「收起」标签,行数不变。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

## Agent Brief

**Category:** bug

**Summary:** 盘点模型在构造时就把展示行截到上限,视图展开时取不到被截掉的行。

**Current behavior:**

盘点(`PortInventory`)的构造函数把全部端口排序后,只保留前 limit 行放进展示行,
另存一个总数。端口功能层构造盘点时传的 limit 就是卡片默认展示上限(20)。视图里
「显示全部」的做法是展开时取展示行的全部——可展示行本身已经只有 20 行,所以展开后
行数不变,只是把末行标签换成「收起」。以上由读代码得出,没有起 app 验证。

**Desired behavior:**

端口超过上限时,末行「显示全部(另 N 个端口)」点下去列出全部端口(保持端口号升序),
标签换成「收起,只看前 20 个端口」;再点收起回到前 20 行。总数不超过上限时不出现
末行。新一轮扫描到来后保持用户当前的展开状态。

**Key interfaces:**

- 盘点模型:展示行与总数的关系要能支撑「先截断显示、展开看全量」。建议模型保留
  全部排序后的行,并提供「按上限取前若干行」的方法;「是否被截断」与「总数」的语义
  不变。若改了构造函数参数的含义,同步修改调用方与测试。
- 视图:展开态取全量,收起态取前上限行;「另 N 个」只在收起态计算。
- 功能层:构造盘点时不再因为展示上限而丢弃数据。

**Acceptance criteria:**

- [ ] 端口数超过上限时,点「显示全部」后行数等于总数;点「收起」回到上限行
- [ ] 收起态末行的「另 N 个端口」里 N = 总数 − 上限;展开态不再出现「另 N 个」
- [ ] 端口数不超过上限时没有末行
- [ ] 核心包单测:截断与展开两种取法都有断言(先写失败测试)
- [ ] 现有端口相关测试全绿

**Out of scope:**

- 行形态、结束进程的确认流、扫描频率
- 端口卡、排行、项目卡三处「截断展开行」的合并(属于另一项重构)
