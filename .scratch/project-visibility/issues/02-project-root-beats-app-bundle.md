# 02 — 项目根归因优先于 App 归属:layerSelf 判定顺序对调(自 01 勘误拆出)

**What to build:** 归组引擎自身归属的判定顺序对调:`GroupingEngine.layerSelf`
(Packages/PulseCore/Sources/PulseCore/GroupingEngine.swift:477)现在先判 App 归属
(`.app` 容器谓词)后判项目归因(cwd/argv 命中项目根),bundle 命中即返回、项目根
没机会发言。改为**项目归因整层先于 App 归属**(层内顺序不变:cwd 优先、argv 次之),
bundle 退为项目未命中时的兜底。

**用户痛点(2026-10-25 用户再次立题,原话"App 的优先级优于项目根……我希望项目根
的优先级更高,把那些进程应该合并到项目根里面"):** 01 号票 2026-10-23 诊断有误——
"引擎已经是项目优先"不成立(详见 01 的勘误评论):项目层只先于**父链继承**,
不先于**自身 App 归属**。可执行在 `.app` 容器内、cwd 命中项目根的进程
(01 样本没覆盖这一类)现行全归 App。两个放大器:

1. `appContainerPrefix` 放宽口径(2026-10-16)把 `/Applications/Xcode.app/Contents/
   Developer/Toolchains/...` 下的 swift-frontend / clang 等编译器全归 Xcode.app——
   构建项目时编译大头记在 Xcode 头上,项目组近乎为空;
2. ZCode agent 会话的 Helper / node(可执行在 ZCode.app 内)cwd 在项目根里,
   现行规则下归 ZCode.app。

改后这些进程归项目组(命中 `.worktrees/<名>` 仍显示"项目名 @ 名"),用户能直接
回答"哪个项目在消耗资源"。主榜单与三个模块排行卡(能耗影响/读写最多/每进程流量)
吃同一份 RoundContext.groups,翻转全局一致生效。

**与 01 的分工:** 本票只修"cwd/argv 命中根却被 bundle 抢走"的半边;01 保留
"cwd 根本没命中根"(draft 目录 / 项目父目录 / `/` 与 home / /tmp worktree)的
半边及其 A–E 候选。01 的候选 B(宿主下钻标注)与本票互斥视角,triage 应两票同看。

**Blocked by:** None

**Status:** done

**拍板(2026-10-25 triage,用户定)**:翻转范围 = **A 无条件翻**(cwd/argv 命中项目根即归项目,不设可执行/宿主门槛——与评审 S4"不设名单闸"精神一致);附加需求 = **下钻明细给来自 .app 容器的进程显示宿主 App 徽标(小图标 + 名称)**,拍 A 放弃的"App 全量成本视角"由此在下钻里补回可读性。另三点按票面倾向记档无异议:argv 命中一并压过 bundle;历史存量不迁移、新样本向前按新口径;不补 ADR,只改 GLOSSARY 措辞(与 ADR-0005 ④ 的轴区分已在上文记档)。

## Agent Brief

**Category:** enhancement
**Summary:** 归组引擎自身归属判定顺序对调——项目归因(cwd/argv 命中项目根)先于 App 归属(.app 容器);下钻明细为容器进程加宿主 App 徽标。

**Current behavior:**
`GroupingEngine` 的自身归属判定(`layerSelf`)先做 App 容器判定(含放宽口径:
/Applications、/Users 下容器内进程归宿主 .app),命中即返回;项目归因只在非容器
进程上尝试。后果:可执行在 .app 容器内、cwd/argv 命中项目根的进程(agent 宿主
Helper、Xcode 工具链 swift-frontend/clang 等)一律归 App 组,项目组看不到构建与
agent 开销——用户的"哪个项目在消耗资源"读不出来。

**Desired behavior:**
- 项目归因整层先于 App 归属,层内顺序不变(cwd 优先、argv 次之);App 容器判定
  退为项目未命中时的兜底。
- 系统判定(知名系统进程)仍最先;父链继承(活链 + 出生登记)走同一判定函数,
  自动跟随新序。
- 项目根为空时行为不变(既有"退化归宿主 App"口径的用例保持绿)。
- 下钻明细:进程行的可执行路径命中 App 容器判定(引擎公开的容器口径谓词,判定
  只有这一份)时,行内显示宿主 App 小图标 + 宿主名;非容器进程不显示。宿主名与
  App 组显示名同口径(CFBundleName 优先,缺省退 bundle 目录名去 .app 后缀)。

**Key interfaces:**
- `GroupingEngine.layerSelf`:两段判定对调;引擎头注释"判定顺序"列表与
  `GroupingConfiguration` 注释措辞同步。
- `appContainerPrefix`:**不动谓词本身**;下钻徽标复用它从进程可执行路径派生
  宿主 bundle 路径(公开口径,别写第二份容器判定)。
- `AppIconCache.icon(forBundle:pointSize:)`:下钻徽标复用此预栅格化通道,不另起
  图标管线。
- `SelfAttributionCache`:不动(身份三元组键;项目根变化已自会作废)。
- 下钻进程行模型(如 `ProcessRowModel`)需携带宿主 bundle 路径/名,或由视图层
  从进程可执行路径现场派生——实现自选,但判定必须走引擎公开口径。
- `GLOSSARY.md`:"App 归属"/"项目归因"两条措辞对调优先级描述;"孤儿进程"条
  顺笔。
- 代码注释引用工单写全名 `project-visibility/02`。
